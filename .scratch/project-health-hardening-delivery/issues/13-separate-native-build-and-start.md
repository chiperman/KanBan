## 验收标准

- [ ] 依据 07 已验证的运行环境检查架构、Node 兼容性和扩展版本；兼容产物存在时生产启动不调用 Cargo。
- [ ] 缺失、过期或不兼容产物明确失败，提供可执行的构建/修复路径，不静默加载错误二进制。
- [ ] 显式构建仍能准备和签署有效产物，开发模式有明确按需构建流程。
- [ ] 原生模块与 Keychain 入口可正常加载，不回退到明文秘密存储；不读真实凭证完成基础集成验证。
- [ ] 受控工具链验证调用和错误传播，真实 macOS 产物加载单独验收；记录实际启动前后耗时。

## 依据与最小范围

现有开发、构建及生产启动前置步骤均调用原生构建/复制/签名；额外时长未实测，不宣称每次均完整重编译。

依赖 07 的受支持版本契约；保持现有 macOS 目标，不扩大 OAuth 或跨平台范围。

## 验证方式

脚本级用受控子进程验证，集成级以真实兼容产物启动应用；模拟工具链通过不能替代实际产物验收。

沿用现有最高业务入口。自动化样例、真实运行和未执行检查分别报告；审查快照不替代修改后验收。测试和恢复使用隔离数据，不能访问所有者凭证或破坏其业务库。

## 风险与收益

中；涉及原生兼容与签名，收益为降低运行启动对构建链的依赖。
