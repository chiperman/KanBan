## 验收标准

- [ ] 声明的 Node、包管理器和 Rust 版本来自依赖要求与实际验证，不把单次复现版本直接当作全面支持承诺。
- [ ] 声明环境中冻结锁文件安装、类型检查、默认单元测试、应用启动及正式日结 CLI 启动均符合契约。
- [ ] 不支持的运行环境在明确的早期检查失败，错误可指导切换到受支持版本。
- [ ] 区分原生编译所需工具与运行所需环境；包管理器声明匹配锁文件，Rust 声明匹配 edition 和本地补丁。

## 依据与最小范围

审查缺少运行时和包管理器版本声明；Node SQLite、类型转换以及原生 Rust 扩展均有实际兼容前提。

依赖 02，因为本项承诺的完整运行环境验收包含正式日结可启动；不引入无关版本升级或多平台支持。

## 验证方式

复用启动脚本契约、CLI 子进程和既有安装/应用验收，原生产物兼容证据单独记录。

沿用现有最高业务入口。自动化样例、真实运行和未执行检查分别报告；审查快照不替代修改后验收。测试和恢复使用隔离数据，不能访问所有者凭证或破坏其业务库。
