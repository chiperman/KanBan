# 11: 合并会话活动通知

**What to build:** 所有者连续输入时会话活动请求被合并，正常操作不会误锁，真正空闲仍按原时限锁定。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Phase:** 本迭代处理
**Priority:** 中
**Parent:** 原项目健康度规格 · 07 — 合并会话活动请求并保持锁定边界

**Approval:** 2026-09-10 所有者确认 16 个执行切片及阻塞关系；本次授权仅为发布 Ticket，未授权代码实施。

## 验收标准

- [ ] 突发输入及同一次触控的重叠事件产生有界请求，同一时刻不会因活动重复产生多条在途通知。
- [ ] 每次真实交互更新本地活动时刻；持续操作在服务端到期边缘仍不误锁，必要尾沿发送保留安全余量。
- [ ] 完全空闲按既有期限锁定；明确 401 或会话失效立即锁定，网络失败不能无限延长会话。
- [ ] 卸载清理监听、定时器和后续通知；隐藏页面不新增无真实活动的保活心跳。

## 依据与最小范围

会话守卫对每个按键、指针和触控活动直接发起通知，缺少节流与在途合并。

仅合并活动通知，不修改空闲时长、不引入后台保活。

## 验证方式

复用恢复与会话锁定浏览器测试，通过可控时间、实际交互和 HTTP 请求观察验证行为。

沿用现有最高业务入口。自动化样例、真实运行和未执行检查分别报告；审查快照不替代修改后验收。测试和恢复使用隔离数据，不能访问所有者凭证或破坏其业务库。

## 风险与收益

低至中；到期竞态是重点，收益为减少重复请求和服务端写入。

## 执行边界

只实现本 Ticket。保留既有未提交改动；实施前核对当前代码与领域契约，并给出最小变更文件清单。代码位置与函数证据在父级审查资料中查找，本 Ticket 不固定实现路径。
