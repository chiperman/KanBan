# 04: Passkey 挑战单次消费

**What to build:** 所有者注册与登录时，挑战具备服务端时效、用途绑定和单次消费；合法零计数器 Passkey 可以继续正常使用。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Phase:** 立即处理
**Priority:** 高
**Parent:** 原项目健康度规格 · 04 — 使 Passkey 挑战具有服务端时效和单次使用约束

**Approval:** 2026-09-10 所有者确认 16 个执行切片及阻塞关系；本次授权仅为发布 Ticket，未授权代码实施。

## 验收标准

- [ ] 注册和登录挑战由服务端记录签发上下文、用途和到期时间；未签发、过期、上下文或用途不符的挑战均被真实验证入口拒绝。
- [ ] 挑战原子消费；同一有效断言并发提交最多一次成功，重复提交不再签发会话或创建凭证。
- [ ] 零计数器凭证以新挑战可以继续登录；服务器重启不会使已失效挑战重新有效。
- [ ] 同一浏览器重新签发使同用途旧挑战失效；多标签页得到重新开始提示，不发生交叉注册或登录。
- [ ] 继续验证签名、origin、RP-ID 和凭证归属；不增加第二所有者或公开注册。
- [ ] 现有 TOTP 防重放、限流、恢复与锁定回归通过；服务端挑战不进入业务备份。

## 依据与最小范围

审查用合成密钥生成真实签名断言，验证库重复接受相同零计数器断言；实际重放要求取得此前有效响应及对应挑战。

只增加认证挑战生命周期；存储的原子性和共享范围匹配实际部署。Cookie 传输配置由 05 独立交付，不成为本项阻塞。

## 验证方式

复用所有者认证浏览器测试与虚拟认证器；通过真实 HTTP 入口验证并发、重放和可控时间边界，不只调用验证库。

沿用现有最高业务入口。自动化样例、真实运行和未执行检查分别报告；审查快照不替代修改后验收。测试和恢复使用隔离数据，不能访问所有者凭证或破坏其业务库。

## 风险与收益

中；涉及注册、多标签页和会话创建，收益为关闭挑战重放路径。
