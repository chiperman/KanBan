# 05: 认证 Cookie 传输约束

**What to build:** 所有者在 HTTPS 下使用受到安全传输约束的认证 Cookie，同时现有 localhost HTTP 登录仍可用。

## 验收标准

- [ ] HTTPS 场景的挑战、会话及相关认证 Cookie 设置适用的 Secure 标志；保留 HttpOnly、SameSite 和正确的有效期。
- [ ] 现有 localhost HTTP 注册、登录和退出可以完成，不因 Secure 配置丢失必要 Cookie。
- [ ] 安全传输判断依据可信部署配置，不被任意客户端伪造的转发头降级或改变。
- [ ] 退出、失败清理和锁定能够删除相同作用域的 Cookie，浏览器端无残留有效会话。
- [ ] 分别覆盖 HTTPS 与本机 HTTP 的响应头和浏览器行为，不将此修复等同于服务端挑战防重放。

## 依据与最小范围

审查发现认证 Cookie 未设置 Secure；实际明文暴露取决于访问和部署方式，不能据此宣称会话已泄漏。

仅统一认证 Cookie 传输与作用域策略；不改变会话时长和认证方式，与 04 可独立落地。

## 验证方式

沿用认证 HTTP/浏览器入口；使用受控 HTTPS 配置验证设置与删除 Cookie 的完整生命周期。

沿用现有最高业务入口。自动化样例、真实运行和未执行检查分别报告；审查快照不替代修改后验收。测试和恢复使用隔离数据，不能访问所有者凭证或破坏其业务库。
