# 08: 单日观测更新避免扫描全部历史

**What to build:** 成功刷新或维护手工资产记录时，写入某一日观测不再读取无关多年历史，当日基准和每日趋势观测保持现有语义。

**Blocked by:** None (can start immediately)

**Status:** resolved

**Phase:** 本迭代处理
**Priority:** 中
**Parent:** 原项目健康度规格 · 06 — 按来源和日期限制历史读取并消除逐行子查询

**Approval:** 2026-09-10 所有者确认 16 个执行切片及阻塞关系；本次授权仅为发布 Ticket，未授权代码实施。

## 验收标准

- [ ] 单日更新按目标上海日期定位数据，其读取工作量不随无关历史天数增长；不改变既有事务一致性。
- [ ] 相同样例前后结果等价：首次完整批次建立当日基准，后续完整批次更新趋势，部分失败和单来源刷新不伪造完整观测。
- [ ] 手工记录编辑、删除与最近值回退、缺日保留、历史汇率和断开来源规则保持。
- [ ] 以 30/365/3650 天合成历史比较工作量与结果，记录测量环境；不把固定 SQL 条数写成行为断言。

## 依据与最小范围

审查的单日观测更新先读取全部历史查找日期；3650 天合成样例中单日更新产生大量查询。

只改变单日定位与写入路径所需读取，不连带重写全历史读取接口；不依赖其他查询优化或大模块提取。

## 验证方式

从现有刷新及手工记录业务入口写入真实临时 SQLite，检查持久事实和规模变化。

沿用现有最高业务入口。自动化样例、真实运行和未执行检查分别报告；审查快照不替代修改后验收。测试和恢复使用隔离数据，不能访问所有者凭证或破坏其业务库。

## 风险与收益

低至中；需要保护历史写入语义，收益随历史增长。
