# 25 — 收拢资产来源接入模块

**What to build:** 把分散在大型前端条件分支和各平台重复 preview/confirm 路由中的接入编排收拢为一个深模块，在不改变现有用户流程和安全规则的前提下提高新增来源、测试和故障修复的局部性。

**Blocked by:** None

**Priority:** P2

**Status:** resolved

- [x] 定义一个小而完整的资产来源接入接口，统一表达“输入授权材料 → 权限验证 → 范围预览 → 确认前重新校验 → 原子保存 → 取消/过期清理”。
- [x] 长桥、Binance、OKX、Bitget、Ethereum 和 BNB Smart Chain 作为该 seam 下的 provider adapter，保留各自 OAuth、区域、账户模式和公开地址差异。
- [x] 路由只承担所有者鉴权、输入解析和 HTTP 映射；预览 claim/release/complete、重新校验、账户范围防变更和连接提交逻辑不再复制到每个平台路由。
- [x] 前端来源选择、字段配置、按钮文案和预览说明由 provider 描述驱动，减少 `asset-source-flow.tsx` 中持续增长的 provider 条件分支。
- [x] 敏感凭证只存在于服务端接入模块和 SecretStore；公共预览类型继续排除凭证正文。
- [x] 新模块的接口测试覆盖成功、权限拒绝、预览过期、重复确认、确认前身份变化、提交失败清理和并发确认。
- [x] 现有六类来源浏览器测试全部保持通过，用户可见流程、错误文案和真实来源权限边界不发生非必要变化。

## 审查证据

- 2026-07-27：`src/ui/asset-source-flow.tsx` 已有 457 行并集中处理六类来源。
- Binance、OKX、Bitget 的 preview/confirm 路由重复所有者鉴权、预览生命周期、重新校验、连接提交和错误恢复，仅平台字段与少量范围检查不同。
