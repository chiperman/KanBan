# 29 — 单独刷新资产卡片

**What to build:** 让所有者在某个资产来源异常或数据过期时，可以直接在对应资产卡片上手动刷新该来源，而不必重新读取其他正常来源。

**Blocked by:** 08 — 自动刷新与过期数据

**Status:** resolved

**Adjusted by:** `.scratch/personal-asset-dashboard-rebuild/issues/06-source-health-and-recovery-experience.md`; `.scratch/asset-refresh-redesign/spec.md`

## 验收标准

- [x] 每个已连接资产来源卡片都有明确且可访问的“刷新”入口。
- [x] 点击卡片刷新只向同步服务提交该卡片对应的 `sourceId`，不按平台类型猜测，也不刷新其他来源。
- [x] 卡片内显示刷新进行中、成功或失败反馈；刷新期间只禁用当前卡片的刷新按钮。
- [x] 成功后更新该来源卡片、总资产与当天趋势观测；失败时继续保留最后成功快照。
- [x] 已断开的来源不提供刷新入口；无效、已断开或缺少只读凭证的目标请求被服务端拒绝。
- [x] 既有全量手动刷新、自动刷新、EVM/非 EVM 调度语义保持不变。
- [x] 聚焦浏览器测试证明目标来源被刷新，其他来源的金额与调用次数不变。

## 答案

- 刷新 API 新增可选 `sourceId`，同步服务只读取该 ID 对应的已连接来源；既有 `all`、`evm`、`non-evm` 范围保持不变。
- 每张已连接资产卡片新增“刷新”按钮和卡内进行中、完成、失败反馈；单卡刷新期间只禁用当前按钮。
- 服务端拒绝不存在、已断开、缺少只读凭证以及同时指定来源范围的单来源请求。
- 单来源成功后仍由现有同步链路更新来源快照、总资产和当天趋势观测；失败继续保留最后成功数据。
