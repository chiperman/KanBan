# 02 — 所有者登录与受限卡片隔离

**What to build:** 让唯一所有者能够通过 Passkey 登录并在同一公开主页中解锁敏感内容，同时让访客看到不含真实数据的受限卡片遮罩。访问控制必须由服务端和数据边界执行，不能只依赖前端隐藏。

**Blocked by:** 01 — 公开主页与应用验证骨架

**Status:** ready-for-agent

- [ ] 系统只允许预置的唯一所有者登录，不提供公开注册入口。
- [ ] 所有者可以使用 Passkey 完成登录，失败或取消后仍停留在安全的访客状态。
- [ ] 访客点击受限卡片后进入登录流程，成功登录后在原页面位置看到敏感内容。
- [ ] 未登录 HTML、序列化页面状态、接口响应和浏览器网络流量中均不存在真实敏感信息。
- [ ] 受限卡片只使用安全占位模型呈现磨砂或设计化遮罩，不对真实数据进行 CSS 模糊。
- [ ] 访客不能通过修改客户端状态、请求参数或直接访问私密接口取得敏感信息。
- [ ] 所有者退出登录后，敏感内容立即恢复为受限卡片且不残留在客户端缓存视图中。
- [ ] 浏览器级测试覆盖访客、登录成功、登录失败和退出登录四条完整路径。
