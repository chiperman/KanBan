# 23 — 无凭证业务数据备份与恢复

**What to build:** 为本地优先的个人资产看板提供可验证、可恢复且不携带任何授权凭证的业务数据备份闭环，避免设备或数据库损坏造成布局与历史快照永久丢失。

**Blocked by:** 21 — SQLite 业务数据持久化

**Priority:** P1

**Status:** resolved

- [x] 所有者可以导出包含资产卡片、来源身份、历史快照、布局和隐藏状态的版本化备份。
- [x] 备份不得包含 API Key、API Secret、Passphrase、OAuth Token、PKCE 材料、SecretStore 密文/引用、Passkey、密码派生材料或 TOTP 密钥。
- [x] 备份明确提示其仍包含敏感资产数据，并以 `0600` 创建本地文件。
- [x] 恢复前验证格式版本、校验和、唯一约束和引用完整性；验证失败不得覆盖当前数据。
- [x] 恢复使用事务或临时数据库完成，成功后再原子切换；中途失败时当前数据库保持可用。
- [x] 恢复的来源默认为已断开历史来源，不得在缺少凭证时自动同步、伪造连接状态或产生空凭证引用。
- [x] 提供恢复预演结果，清楚列出将恢复的来源数、卡片数、快照日期范围和会被替换的数据范围。
- [x] 自动化测试覆盖正常导出/恢复、敏感字段扫描、损坏备份、旧版本迁移、重复恢复和恢复回滚。

## 审查证据

- 2026-07-27：仓库内没有业务数据备份、恢复预演或恢复验证闭环；本地存储仍是资产历史的单点故障。

## 评论

- 本 Ticket 不备份平台授权材料，也不承担跨设备自动同步；凭证需要所有者在恢复后按来源重新授权。
- 2026-07-28：增加版本化 SHA-256 业务数据备份、`0600` 原子写入、恢复预演和所有者认证 API；恢复来源统一标记为断开且不生成凭证引用。
- 自动化验收：Ticket 23 定向测试 7/7、SQLite 联动测试 16/16 通过；完整套件构建成功且 124/126 通过。两条既有锁定页隐私测试仍把合法显示的上海时钟误判为资产快照时间，本 Ticket 未修改相关页面、时钟或断言。
