# 20 — 首次启动所有者预置闭环

**What to build:** 修复全新安装时从锁定首页无法发现所有者 Passkey 预置入口的问题，让所有者从根页面即可完成首次预置并回到正常登录流程。

**Blocked by:** None

**Priority:** P0

**Status:** ready-for-agent

- [ ] 系统尚无所有者凭证时，根页面显示明确的首次预置入口，不再把“使用 Passkey 登录”作为唯一主操作。
- [ ] 所有者可以从根页面进入一次性 Passkey 预置，无需预先知道或手动输入 `/setup`。
- [ ] 预置完成后提供明确的返回登录操作；预置不会被误认为已经登录。
- [ ] 已存在所有者凭证时，根页面只提供登录，`/setup` 继续返回 404，不形成公开注册入口。
- [ ] 未认证 HTML、页面状态、接口和网络响应继续不包含资产、来源、地址或凭证信息。
- [ ] 浏览器测试必须从没有任何所有者凭证的 `/` 开始，覆盖“首次预置 → 返回首页 → Passkey 登录”的完整路径。
- [ ] 失败、取消和不支持 Passkey 时提供可执行的恢复说明，不留下只有错误提示的死路。

## 审查证据

- 2026-07-27：全新测试环境打开根页面后只有“使用 Passkey 登录”；点击得到“所有者尚未预置登录凭证”，页面没有前往预置流程的入口。
- `src/app/setup/page.tsx` 已有一次性预置能力，问题集中在根页面的首次启动状态识别和入口衔接。

## 评论

- 保持产品为单所有者、无公开注册；本 Ticket 只补全首次启动闭环，不扩展账户模型。
