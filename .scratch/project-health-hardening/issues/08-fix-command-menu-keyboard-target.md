## Problem Statement

菜单容器拦截所有子元素冒泡的 Enter 并执行 activeIndex 命令；Tab 聚焦关闭按钮或另一命令时，焦点目标与执行目标可能不一致。

**审查证据：** 审查确认容器 keydown 未限制 Enter 来源，直接执行当前高亮命令。未把静态检查声称为浏览器实测。

**位置（模块/函数）：** CommandMenu 容器的 onKeyDown / Enter 分支。

## Solution

避免按 Enter 关闭或选中按钮时执行另一条命令。

**修改风险：** 低。

## User Stories

1. 作为所有者，我希望使命令菜单执行正确的键盘目标，以便避免按 Enter 关闭或选中按钮时执行另一条命令。
2. 作为维护者，我希望用既有业务入口验证本 Ticket，以便修复不改变已接受的领域语义。
3. 作为所有者，我希望验收区分合成样例、自动化回归与真实环境结果，以便准确判断剩余风险。

## Implementation Decisions

- 搜索输入框中的 Enter 执行高亮结果；命令按钮和关闭按钮使用自身原生键盘行为。
- 保留方向键导航、Tab、Escape、焦点恢复与输入法组合输入；复用现有视觉 Token 和组件，不改菜单布局。

## Testing Decisions

扩展现有命令菜单视觉语言浏览器测试，使用真实键盘焦点与操作结果验收，不仅直接调用事件处理器。

测试边界为建议方案，已向所有者征询，本规格发布时未收到确认；实施前以其反馈更新。测试只验证对外结果，避免对搬迁后的内部函数或特定 SQL 文本做镜像断言。

**验收标准：**

- [ ] 浏览器先复现 Tab 聚焦关闭按钮后 Enter 的错误，再验证仅关闭且不执行命令。
- [ ] Tab 聚焦某命令后 Enter 只执行该命令一次；搜索输入 Enter 执行当前高亮项。
- [ ] 方向键、Escape、空结果和中文输入法组合输入不会误执行；关闭后焦点回到合理触发位置。

## Out of Scope

不重设计界面、不新建视觉语言、不引入新命令体系。
