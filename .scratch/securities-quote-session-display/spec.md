# 证券持仓表展示交易时段行情

## 状态

已实现并完成确定性适配器与生产形态浏览器验收；未安装 `launchd`，也不以真实账户或真实正式日结任务作为本 Ticket 的验收前提。

## 调研结论

- 当前 KanBan 的 Longbridge Keychain 原生读取链路每次拉取证券报价后，只传递 `symbol`、`lastDone`、`prevClose`、`timestamp`；持仓模型和表格因此只有“Longbridge 实时行情 + 时间”，没有报价所属时段。
- 当前使用的官方 Rust SDK `QuoteContext.quote()` 实际还能读取证券的交易状态，以及美股独立的盘前、盘后和夜盘报价对象；每个对象都有价格和成交时间。原生桥接目前没有把这些字段交给 TypeScript。
- 官方 Quote 拉取接口的行情权限独立于 App/Web 行情权限；美股默认包含盘前、盘后与夜盘，其中夜盘要求显式开启 SDK 配置。港股 BMP 请求超过 20 个标的时，官方会返回延迟行情。因此不得把任何成功响应默认称为“实时”。
- 现有正式日结已通过官方日 K 的常规盘数据重估证券，并与当前资产刷新、日初基准和每日趋势观测分离。本 Ticket 只能扩充当前报价证据，不能改变该日结边界。

## 目标

在不重做资产卡片、不改动“现价 / 成本”列标题或成本价展示的前提下，证券持仓表为当前价格增加可核验的交易时段和行情时间。加密资产保持 `24h` 语义，不获得任何证券交易时段标签。

## 领域定义

| 值 | 含义 | 可以由什么证据产生 |
| --- | --- | --- |
| 常规盘 | 标的在其官方常规交易时段内的报价。 | Longbridge 直接返回的常规盘会话证据；不得按本机时钟推断。 |
| 盘前 | 美股盘前交易的报价。 | Longbridge 明确标注的盘前报价对象及其成交时间。 |
| 盘后 | 美股盘后交易的报价。 | Longbridge 明确标注的盘后报价对象及其成交时间。 |
| 夜盘 | 美股夜盘交易的报价。 | Longbridge 明确标注的夜盘报价对象及其成交时间；夜盘读取未启用、无权限或未返回时不伪造。 |
| 未知时段 | 有价格或账户估值，但来源未能证明该价格所属交易时段。 | 缺少、冲突或无法解析的会话证据；旧快照也属于这一类。 |
| 加密资产 24h | 加密资产连续市场中的一次价格观测。 | `assetClass=crypto` 的来源价格与价格时间；绝不显示常规盘、盘前、盘后或夜盘。 |

“交易时段”描述的是这一个报价的来源时段，不等价于“市场此刻是否开市”，也不等价于正式收盘价。

## UI 方案

只调整持仓明细表的现价区域：

- Longbridge 紧凑表仍保留“现价 / 成本”列、现价主数字和原有成本价文字。
- 在现价主数字与成本价之间增加一行低强调度等宽元信息：`盘后 · 行情 2026-08-06 05:12`。时间使用看板既有的上海时区格式，保留日期以免周末、节假日和跨日误读。
- 已知常规盘、盘前、盘后、夜盘分别显示对应文字；未知显示 `时段未知 · 行情 <时间>`，时间也不可用时显示 `时段未知 · 时间不可用`。
- 加密资产在同一区域显示 `24h · 行情 <时间>`；不显示证券时段。
- 宽表的“现价”单元使用同一行元信息；“成本”单元不变。
- 不新增一列、不移动市值/数量/盈亏列、不改变成本价精度、币种折算或隐藏敏感金额的行为。元信息同样受现有敏感信息隐藏边界保护。
- 不把每一行做成彩色状态徽章；复用现有次级等宽说明文字和既有 Vibe Token。来源同步失败仍使用卡片已有的 `STALE`/错误表达。

示例仅说明排版，不代表通过本机时间得出的状态：

| 现价 / 成本区域 |
| --- |
| `158.770`<br>`盘后 · 行情 2026-08-06 05:12`<br>`150.500` |

## 数据模型与来源边界

每个持仓可选地带有一份“当前报价证据”，至少包含：

| 字段 | 语义 |
| --- | --- |
| 价格与币种 | 被当前持仓表显示和估值使用的报价。 |
| `session` | 六种领域值之一：常规盘、盘前、盘后、夜盘、未知时段、加密资产 24h。 |
| `quotedAt` | 行情供应商给出的该价格成交/报价时间；不可用时为 `null`，不能用同步完成时间代替。 |
| `observedAt` | KanBan 成功读取该供应商响应的时间，仅用于诊断，不冒充行情时间。 |
| `freshness` | 本次响应确认、保留的旧证据、或无可用报价。它与资产来源整体同步状态分开。 |
| `delivery` | 已证实实时、已证实延迟或未知。未得到供应商直接证明时必须为未知，UI 不得写“实时”。 |
| `provider` | 供应商与原始会话/交易状态枚举，用于适配器诊断；不把未知原始值转换为已知时段。 |

Longbridge 原生边界须在同一只读行情读取中输出以下原始候选，随后由服务器适配器统一选择展示报价：

1. 常规报价候选：主报价价格、时间及官方交易状态。
2. 美股盘前、盘后、夜盘候选：各自价格与时间；夜盘候选只在官方 SDK 配置启用且供应商返回时存在。
3. 报价权限/延迟可判定信息；不能判定时显式为未知。

候选选择规则：

1. 盘前、盘后、夜盘只能由各自明确标记的 Longbridge 候选产生；比较的仅是供应商给出的时间戳。
2. 常规盘只能由供应商明确的常规盘/正常交易状态证据产生。不得因为标的是 `.US`、本机正处于某个钟点、市场日历预计开市，或没有盘外候选而标为常规盘。
3. 多个已知时段候选同时存在时，选择供应商时间戳最新且无冲突的一项作为现价；相同时间而时段冲突、无有效时间或未知原始枚举时，保留可靠价格但将时段设为未知。
4. 不能为一个持仓建立可靠候选时，沿用现有“现价不可用 / 未估值 / 行情未接入”语义；不得补零，不得从账户同步时间构造报价时间。
5. 旧快照没有当前报价证据时保持可读：有现价则显示未知时段和既有可靠价格时间；没有可靠时间则显示时间不可用。迁移不重写历史快照。
6. `assetClass=crypto` 不读取或解释 Longbridge 证券时段候选；它使用 `24h`。现金、基金净值和其他非交易报价不宣称证券时段，默认未知或沿用其现有来源说明。

现有 macOS Keychain、只读 OAuth 和 `market-data` 权限边界不扩大：不新增交易、转账、提现、订单或新的用户凭证。行情可用性仍受 Longbridge 账户实际行情权限和套餐限制；适配器不得把成功 HTTP/SDK 返回等同于全市场、全时段、无延迟的覆盖承诺。

## 与其他记录的隔离

| 记录 | 本 Ticket 可以影响 | 明确不能影响 |
| --- | --- | --- |
| 当前实时快照 | 当前持仓显示价格、报价时段、报价时间和当前市值可使用新选择的报价。 | 不改写来源余额、成本价、数量或账户授权边界。 |
| 日初基准 | 无新增语义。仍是上海自然日首次成功资产观测。 | 不改成开盘价，不按交易时段回写。 |
| 每日趋势观测 | 继续是当天最佳已有资产价值观测，可能反映当前快照。 | 不命名为收盘，不保存或展示为正式时段结论。 |
| 正式日结 | 无新增写入；证券仍只用官方日 K 的常规盘收盘，加密资产仍用同一日结窗口的市场价格。 | 绝不以盘前、盘后、夜盘、当前 `lastDone`、报价时间或当前快照覆盖已确认日结。 |

正式日结的日 K 读取和当前报价读取保持两个独立原生/适配器入口。正式日结任务、其调度、安装和真实运行验收均不属于本 Ticket。

## 刷新与降级行为

- 刷新节奏不变：现有价格刷新和完整持仓刷新在同一链路内携带报价证据；不为显示时段额外创建浏览器轮询、WebSocket 常驻连接或后台任务。
- 成功读取但市场休市：展示供应商最后确认的价格、其已知时段和精确行情时间；不因时间较早就标记来源同步失败，也不把市场“当前休市”倒推成该报价的时段。只有供应商直接返回且适配器已支持时，才可额外显示市场状态。
- 来源刷新失败：保留最后成功的价格、时段与行情时间，沿用来源已有过期状态；不得用失败发生时间或下次重试时间重标时段。
- 单标的报价缺失或无权：已有价格证据可以保留但标为保留/不可确认；从未有可靠报价则显示现价不可用或行情未接入，不用账户总额反推单项价格。
- 供应商延迟：只有已知为延迟时显示“延迟行情”；未知不显示“实时”。港股批量行情的官方延迟规则必须进入适配器测试。
- 非美股：没有供应商明确的盘前/盘后/夜盘候选时，只能显示常规盘的直接证据或未知时段；不套用美股交易钟点。
- 期权：维持既有“期权行情未接入 / 现价不可用”降级，不在本 Ticket 接入期权行情、OPRA 或其他新权限；成本和账户级总额语义不变。
- 加密资产：始终为 `24h`；价格不可用、过期或延迟时使用各自来源已有的真实状态，不借用证券市场状态。

## 验收标准与测试 seam

### 适配器/原生边界

- 可用确定性 Longbridge 响应分别构造常规盘、盘前、盘后、夜盘、未知和无报价场景，断言选择的价格、`session`、`quotedAt`、`freshness` 与 `delivery` 全部来自供应商证据。
- 断言没有任何用本机时钟、时区、交易日历或符号后缀推断盘前/盘后/夜盘/常规盘的分支。
- 夜盘未启用、缺字段、无权限、无效时间戳、相同时间冲突和旧快照都降级为未知，不会误贴已知时段。
- 覆盖行情权限独立、港股超过官方批量阈值的延迟标记，以及部分标的缺失时保留旧证据而不伪造新时间。
- 断言只读凭证、Keychain 引用和对外响应中不出现 Token、密钥或扩大权限。

### 浏览器边界

- 生产形态的 Longbridge 测试替身可以驱动每种报价时段；所有者在证券持仓表中可看到现价、正确时段和上海时间。
- “现价 / 成本”表头、成本价格式、列顺序、持仓盈亏计算和敏感信息隐藏保持既有合同。
- 加密持仓显示 `24h` 而非证券时段；现金、基金净值和期权不被错误标为常规盘或盘外时段。
- 刷新失败后页面仍展示上次行情时间和时段，同时呈现既有过期来源状态；成功但市场休市不会被误标为同步失败。

### 隔离回归

- 当前盘后或夜盘报价可以改变当前持仓显示，但不能改变一笔已完成正式日结中的官方收盘价、交易日、总额或不可变状态。
- 日初基准和每日趋势观测继续按其既有写入规则工作，不能因新增报价时段字段被改名、重算为收盘或迁移覆盖。
- 正式日结的浏览器展示继续明确证券是“官方日 K 常规盘收盘”、加密资产是“采集窗口价格”。

自动化验收使用适配器确定性样本与现有生产形态浏览器测试 seam；真实 Longbridge 行情权限、真实账户、macOS Keychain 和正式日结后台任务只可作为所有者另行授权的人工验收。

## 不在范围内

- 安装、修改、卸载或验收 `launchd` 正式日结任务。
- 修改正式日结的市场日历、日 K 选择、采集窗口、持久化或不可变规则。
- 新建全量行情服务、长连接报价终端、价格告警、下单、交易、转账、提现或任何写权限。
- 接入期权行情、OPRA 权限、期权 Greeks 或期权专用持仓页。
- 改造资产卡片布局、重做持仓表、修改成本价口径、改动盈亏公式或重建历史快照。
- 使用本机时间、上海时间、美股交易时刻、节假日表或符号猜测报价所属时段。
