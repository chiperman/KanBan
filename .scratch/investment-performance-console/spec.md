# 外部资金流水与投资分析运营台

## Problem Statement

个人资产看板已经能够汇总投资资产、保存日初基准和每日趋势观测，但它只知道“某天资产值多少”，不知道资金何时从投资体系外投入、何时被取回。因此：

- 所有者无法可靠判断当前总资产相对自己实际投入的资金究竟赚了还是亏了；
- 今日资产变动和区间资产变动可能包含资金投入、资金取回或内部划转，不能被误称为投资收益；
- 现有资产快照、手工资产记录和平台盈亏都不能替代全局资金流水；
- 所有者无法回答“以完全相同的投入和取回节奏买入标普 500 或纳斯达克 100，今天会怎样”的问题；
- 单页个人资产看板开始承载资产、资金流水、投资分析与设置等不同任务，缺少清晰的导航骨架。

所有者需要一个保留现有 Vibe 视觉语言的个人资产运营台：以独立的外部资金流水作为本金事实来源，在真实资产快照之上计算净投入、累计盈亏和资金加权收益率，并可在可靠基准数据可用时与指数进行同资金流对比。

## Solution

在个人资产看板中增加“外部资金流水”能力，并将产品组织为由共享导航承载的几个所有者专属模块：

- 总览：保留当前总资产、资产来源、持仓和每日趋势观测；
- 资金流水：维护所有外部资金投入与资金取回；
- 投资分析：展示净投入、当前总资产、累计盈亏、资金加权收益率，以及可用时的指数同资金流对比；
- 设置：保留现有本机设置和安全配置。

“外部资金流水”只记录资金跨越投资资产范围边界的事件。平台间转账、买卖证券或加密资产、换币、申购赎回、账户内利息和股息都不创建资金流水。它们继续由资产来源、持仓和资产快照反映。

投资分析始终从资金流水和完整的每日趋势观测实时派生，不把收益结果伪造成新的资产快照。缺少可靠资产估值、历史汇率或指数基准点时，系统明确显示数据不足，不补零、不回填、不把今日汇率重算进历史。

## User Stories

1. 作为所有者，我希望记录每一次从投资体系外投入的资金，以便知道累计本金。
2. 作为所有者，我希望记录每一次从投资体系取回的资金，以便已取回的资金不会被遗漏在总收益之外。
3. 作为所有者，我希望为每笔资金流水记录精确发生时间、金额、原币种和备注，以便历史计算有可追溯依据。
4. 作为所有者，我希望在同一天记录多笔资金投入或取回，以便真实还原我的资金节奏。
5. 作为所有者，我希望更正或删除误录的资金流水，以便分析结果能被修正。
6. 作为所有者，我希望资金流水与资产来源、持仓和手工资产记录分开管理，以免把资产总额或内部操作误当作本金变化。
7. 作为所有者，我希望平台间转账、买卖、换币和申购赎回不影响净投入，以免重复计算收益。
8. 作为所有者，我希望输入一笔最早的历史投入，以便为已有资产历史建立可信的本金起点。
9. 作为所有者，我希望以 USD、CNY 或 HKD 查看净投入和收益，以便与当前计价货币一致地理解结果。
10. 作为所有者，我希望历史资金金额使用发生时可追溯的汇率，而不是今天的汇率，以便历史结果不会随当前汇率变化而被改写。
11. 作为所有者，我希望在缺少可靠历史汇率时看到数据不足，以免不存在的换算被显示为精确金额。
12. 作为所有者，我希望看到累计净投入、当前总资产和累计盈亏，以便直接判断整体赚亏金额。
13. 作为所有者，我希望累计盈亏在取回资金后仍正确反映整体结果，以便不会把已经实现的收益误认为损失。
14. 作为所有者，我希望看到资金加权收益率，以便评价实际投入资金在不同时间点进入市场后的回报。
15. 作为所有者，我希望投资分析只在存在完整终点资产估值和可计算现金流时显示收益率，以便不可靠数据不会制造结论。
16. 作为所有者，我希望资产趋势中的缺失、不完整或过期日期继续如实断线或标示，以便收益分析不掩盖资产历史质量。
17. 作为所有者，我希望选择标普 500 或纳斯达克 100作为对比基准，以便理解主动配置相对广泛市场的结果。
18. 作为所有者，我希望基准模拟采用与我完全相同的资金投入和取回节奏，以便比较的是可实现的替代结果，而不是不同本金条件下的百分比。
19. 作为所有者，我希望周末、节假日和市场休市期间的资金流水有明确的基准生效规则，以便指数模拟可复算。
20. 作为所有者，我希望知道基准数据是总回报数据还是复权 ETF 代理，以便不把股息口径不同的曲线当作同一指标。
21. 作为所有者，我希望基准数据尚未配置、缺失或不可靠时仍可正常使用资金流水和自身收益分析，以便外部数据不可用不会阻塞核心记账。
22. 作为所有者，我希望所有资金金额、收益数字、分析曲线和流水备注只在通过所有者验证后显示，以便继续保护敏感信息。
23. 作为所有者，我希望隐藏敏感信息后资金金额、收益结果和足以推断它们的曲线形状一并隐藏，以便隐私模式真实生效。
24. 作为所有者，我希望从侧边栏快速进入总览、资金流水、投资分析和设置，以便产品扩展后仍然清晰易用。
25. 作为移动端所有者，我希望以适合窄屏的菜单访问相同模块，以便导航不会挤压资产与分析内容。
26. 作为所有者，我希望资金流水与分析数据被包含在凭证无关的业务数据备份和恢复中，以便本机迁移或恢复后历史结论保持完整。
27. 作为所有者，我希望系统从不执行真实入金、取回、交易或划转，以便该产品继续只是资产观察与个人记录工具。

## Implementation Decisions

- 引入“外部资金流水”作为新的领域术语。它包含“资金投入”和“资金取回”两类事件，均指资金跨越投资资产范围边界；它不是平台的充值、提现、交易流水或手工资产记录。
- 外部资金流水按不可重复的记录 ID 保存，允许同一上海自然日多笔记录，并保存精确发生时间。它不是每日一条的资产总额记录。
- 每笔资金流水保存原始金额、原币种、发生时间、可选备注、创建和更新时间；同时保存发生时用于 USD、CNY、HKD 历史展示的可靠换算结果、汇率来源与汇率观测时间。无法可靠换算的目标币种保持不可用。
- 资金流水写入独立的 SQLite 业务数据表，并通过独立的服务端端口、生产实现、内存替身和所有者鉴权 API 暴露。它不读取、保存或修改资产来源凭证。
- 资金流水的创建、修改或删除不得重写资产快照、日初基准或每日趋势观测。它只使投资分析的派生结果更新。
- 净投入定义为累计资金投入减累计资金取回。累计盈亏定义为当前完整总资产减净投入；取回资金必须参与该公式。
- 资金加权收益率使用现金流时点和当前完整总资产的 XIRR 语义计算：资金投入为所有者现金流出，资金取回和终点资产价值为现金流入。无法求解、没有资金投入、没有完整终点资产估值或没有可靠换算时，结果必须是数据不足。
- 收益计算优先使用现有 decimal 金额边界；图表渲染层才将可绘制结果转换为数值。不得把缺失、不完整、过期或无法折算的资产值替换为零。
- 每日趋势观测仍然是总资产历史的唯一来源。资产金额曲线保留现有缺失日期断线契约；净投入可以按真实资金流水形成阶梯变化；累计盈亏和收益率仅在各自所需的可靠数据齐全时形成可展示点。
- “预期收益率”属于目标或预期，不得被当作历史收益或指数基准。若保留，应与实际收益和同资金流基准明确区分。
- 指数对比采用“同资金流虚拟组合”：每笔资金流水以其后第一个相关市场收盘点生效，并按照所选基准的日回报累计；资金取回以相同规则减少虚拟组合。当前虚拟组合价值用于与当前总资产并列比较。
- 指数基准必须使用明确标识的总回报序列；若使用复权 ETF 作为代理，界面必须明确其代理身份。基准价格数据必须缓存其标识、交易日、值、币种、来源和取得时间，以便结果可复算。
- 基准数据提供方、许可和总回报序列可得性是长期口径决策；在接入真实提供方前，基准功能必须显示未配置或数据不足，不得抓取未获确认的网页数据并将其包装为可靠市场事实。
- 业务数据备份、预览恢复和恢复校验必须纳入外部资金流水及已缓存的基准数据；恢复后资产来源仍遵循既有凭证清除和断开策略。
- 创建共享的所有者应用壳，承载总览、资金流水、投资分析和设置。桌面端使用克制的侧边栏；移动端使用等价的紧凑导航。导航必须具备可访问名称、键盘可达性、当前页状态和最小触达尺寸。
- 继续使用项目现有 Vibe 组件、运行时 Token、黑白信息层级、细线和克制状态色。侧边栏和分析页面不得引入第二套后台视觉语言，也不得把红色作为普通激活态或曲线装饰。
- 现有首页继续作为总览入口。资产来源与持仓管理不会因为引入导航而改变其读取、同步、断开或永久删除的安全语义。

## Testing Decisions

- 主要验收接缝是已验证所有者的浏览器流程，并沿用现有可控时钟、所有者会话和服务测试替身。测试应观察用户可见的流水、派生指标、图表状态、导航与隐私结果，而不是断言内部 SQL 或组件状态。
- 为外部资金流水建立 API 行为测试：未认证请求被拒绝；合法的投入、取回、编辑和删除成功；同日多笔记录保留；金额、币种、时间和备注的非法输入得到明确错误。
- 为资金流水持久化建立重启和 SQLite 迁移测试：已有数据库升级后不丢失原有资产来源、手工资产记录、日初基准或每日趋势观测；新流水能在重启后读取。
- 为备份与恢复建立端到端行为测试：导出的业务数据不含凭证；资金流水和基准缓存完整往返；恢复预览如实显示替换范围；恢复后资产来源仍按既有策略断开。
- 为投资分析建立确定性场景测试：多次投入、部分取回、取回后剩余资产、同日多笔流水、历史补录、没有完整终点资产、没有可靠汇率和不完整趋势观测。
- 为资金加权收益率建立可复算样例：结果依赖真实发生时间而非仅日期；无法得到唯一或有效结果时展示数据不足，而不是显示零或无限收益。
- 为指数同资金流模拟建立固定基准数据测试：投入与取回按既定有效交易日处理；周末和休市日映射正确；基准缺点、未配置来源或代理数据均有明确可见状态。
- 为导航与视觉建立浏览器验收：桌面端当前页清晰可辨；移动端无横向溢出；键盘可访问；敏感信息隐藏时不泄露金额、收益、流水备注或可推断的图形。
- 测试将参考现有手工资产记录、每日资产趋势、凭证无关备份恢复和所有者会话的浏览器测试风格，以保证新能力接入已有最高层行为接缝。

## Out of Scope

- 执行真实入金、取回、银行转账、加密资产提现、下单、换币、调仓或签名。
- 自动拉取各资产来源的历史充值、提现、账单或交易流水；这会扩大隐私范围，并且不能在未建立去重规则时替代所有者的外部资金流水。
- 税务核算、已实现/未实现收益拆分、交易级成本法、分红税务、借贷负债、保证金和完整个人收支管理。
- 多所有者、团队协作、公开共享资产数据或公开访问。
- 自动将现有资产快照倒推为历史资金投入；无法可靠证实的历史只能由所有者补录。
- 在未完成数据提供方、许可和基准口径决策前，把任意公开网页、非复权价格或临时数据视为正式指数基准。

## Further Notes

- 当前日初基准、每日趋势观测、今日资产变动和区间资产变动的既有语义不变；它们不是投资收益。
- 资金流水是核心第一阶段；它完成后，净投入和累计盈亏即可先落地，不依赖指数数据提供方。
- 指数对比应作为第二阶段，但数据模型和分析界面需为其保留可靠的不可用状态，而不是为了完整外观伪造曲线。
- 该规格使用现有所有者浏览器验收作为最高测试接缝；它保持个人资产看板的只读资产操作边界，同时允许所有者维护本机业务记录。
