# 06 — 资产来源健康、失败恢复与低噪声提示

**What to build:** 统一来源同步、估值、持仓行情、价格观察与历史覆盖的健康表达，优化手动刷新、失败恢复与过期状态。

**Blocked by:** 03 — 五目的地应用壳与可靠返回路径; 05 — 资产与持仓及来源观察层.

**Status:** resolved

- [x] 数据健康按“来源总额可信度、持仓明细覆盖、价格观察、同步健康、历史覆盖”分层，不要求无意义的持仓对账。
- [x] 失败保留最后成功数据、显示最后成功时间和人可理解原因，并从诊断链接到相应来源的恢复动作。
- [x] 全局刷新和单来源刷新各自只出现在对应职责处；请求中、成功、失败和可重试状态可理解且不堆叠噪声。
- [x] 网络/接口临时失败、超时、过期、未估值与未配置来源均有一致空状态和回退路径。
- [x] 健康概览默认优先显示“需关注来源”，正常来源可展开查看；同一原因影响多个来源时聚合一次并保留每个来源的排查入口。
- [x] 自动化覆盖局部失败、价格刷新不掩盖余额失败、重试、断开、无凭证、历史缺口、隐私、桌面与 390px。

## 答案

- 修改范围：数据健康默认只列出需关注来源，以来源总额、持仓明细覆盖、价格观察、同步状态与历史覆盖分层；正常来源可单独展开，共同原因只聚合一次并保留逐来源详情入口。
- 业务口径：来源同步失败仍展示最后成功总额与时间；持仓明细不足、仅汇总产品或未估值不会被误称为总额异常。全局刷新仅在总览，单来源刷新仅在详情；成功提示在 2.4 秒后收起，失败保留可理解原因和重试入口。
- 自动化证据：`pnpm typecheck`、`pnpm build`、`pnpm test:unit`（17/17）与 `pnpm exec playwright test e2e/data-health-diagnostics.spec.ts`（5/5）通过。
- 浏览器验收：隔离测试服务覆盖默认需关注、正常来源展开、历史缺口筛选、键盘进入来源详情、单来源失败后保留总额与重试、全局成功提示自动收起，以及桌面与 390px 锁定隐私和无横向溢出。
- 真实来源未覆盖项：未调用真实账户、真实凭证或网络来源；所有刷新与失败情形均使用隔离替身。
- 迁移影响和风险：无数据库迁移，不改写来源、快照、账本、布局或凭证。真实网络的限流与临时失败仍需在所有者明确授权后单独人工验收。
