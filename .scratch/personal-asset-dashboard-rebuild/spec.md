# KanBan 个人资产看板全面产品重构

## 产品定位

KanBan 是本地优先、单所有者、私有、只读的个人资产汇总与分析 App。它帮助唯一所有者可信地理解当前投资资产、资产走势、累计投入与投资盈亏；它不执行交易、资金操作、签名或凭证外泄，也不是完整个人财务软件。

本规格取代现有产品规格中关于已认证信息架构、资金本金、收益分析和数据可信度的旧范围；仍复用既有来源接入、来源生命周期、日初基准、每日趋势观测、正式日结、SecretStore/Keychain、Passkey/TOTP 和凭证无关备份边界。

## 核心判断

用户每天打开后必须能在不进入低频管理页的情况下回答：

1. 当前全部投资资产是多少，以及这个金额是否完整、是否包含过期数据；
2. 资产在近几日、周、月、季度、年及自定义区间如何变化，数据实际覆盖哪些日期；
3. 累计投入多少本金，当前组合实际赚亏多少；
4. 每个资产、持仓和来源的现价、市值、区间变化与可获得的平台盈亏；
5. 哪些数据是来源账户/平台总额真相，哪些仅是持仓观察或行情覆盖。

## 领域与财务口径

- **来源总额**：自动来源返回的账户或平台总额。它是该来源进入组合总资产的权威金额；现金、负债抵扣、未结算资产、仅汇总产品或接口覆盖差异可能使它不等于持仓明细之和。
- **持仓明细**：当前持仓的观察性明细。它优先展示可靠价格、市值、价格变化与平台原生盈亏；无法可靠获得成本或平台盈亏时明确降级，不推断或补造。
- **计价货币**：默认 USD，可切换 CNY、HKD。换算统一使用长桥参考汇率观察，并记录货币对、来源、观测时间和历史数值；无可靠参考率时目标币种不可用，不回退到其他平台、固定汇率或当前汇率。
- **投资资金进出账本**：记录跨越整个投资资产范围的初始投入、外部入金和外部出金。平台间内部转账、买卖、资产互换、换币、申赎、利息或分红不写入账本。
- **累计净投入**：截至某一时点的初始投入与外部入金之和，减外部出金。
- **组合投资盈亏**：当前完整总资产减累计净投入。该公式保留已取回资金的经济结果，不能把外部入金误判为收益。
- **区间资产变化**：区间尾端完整资产观测减起点完整资产观测；它可以包含资金进出，不是收益。
- **区间投资盈亏**：区间资产变化减去该区间内的净外部投入。
- **区间投资盈亏比例**：使用资金发生日加权的 Modified Dietz 分母计算；只在端点、账本折算与分母均可靠时显示，并明确说明不年化、不替代税务或交易级收益率。

## 数据模型与迁移

- 新增 `investment_cashflows` 业务表，保存不可重复 ID、类别（初始投入/外部入金/外部出金）、发生时间、原始金额、原始币种、备注、创建/更新时间，以及 USD/CNY/HKD 的可用换算值、汇率来源和汇率观测时间。
- 初始投入是组合历史的可选起点事实；同一组合只能保留一个最早的初始投入。后续本金变化使用外部入金或外部出金，避免把同一笔资本重复记入。
- 迁移只增量创建表与接口，不改写资产来源、当前快照、日初基准、趋势观测、正式日结、卡片布局或凭证引用。整个迁移在 SQLite 事务内验证；旧版本应用忽略新增表即可回退。
- 创建、编辑、删除或历史补录资金记录只重算派生分析，不改写或补造任何资产观测。历史没有完整资产观测时，不显示伪造净值、收益曲线或区间结论。
- 手工资产记录只形成其对应上海自然日的来源观测；相邻日期没有真实观测时保留断点，不能用旧记录向前或向后延展成连续总资产或收益曲线。
- 业务备份、恢复预演和恢复校验包含账本数据和其汇率观察，但继续拒绝所有凭证、令牌、私钥、Passkey 和 TOTP 材料。

## 信息架构

### 总览

总览只服务当日判断：总资产与可信度、累计净投入与组合投资盈亏摘要、短趋势、来源摘要、显示币种、金额隐藏和全局刷新。资金补录提供清晰入口，但完整账本、编辑、删除和收益解释不常驻此页。

### 资产与持仓

此页面以可比较的资产与持仓为职责：跨来源持仓列表、来源/资产类别/估值状态筛选、当前价格、市值、可用价格变化与平台原生盈亏。每个来源的账户或平台总额、总额估值完整性、持仓明细覆盖、仅汇总产品及未估值资产始终独立表达，持仓合计不能取代账户总额。

持仓没有可靠的累计成本、平台盈亏、价格历史或区间端点时，只显示可获得的当前观察并明确“数据不足”；不根据来源总额差额、其他来源价格、交易猜测或零值补造单项收益、成本或走势。

### 收益分析

此页面是资金账本与收益解释的唯一归属：完整账本的录入、编辑、删除、历史补录、累计净投入、组合投资盈亏、区间资产变化、区间投资盈亏、比例、实际覆盖日期、汇率来源与数据不足说明。

### 资产来源

此页管理来源列表、来源详情、接入、重新授权、手工资产和单来源恢复。数据健康是该模块下的只读诊断入口：显示同步、估值完整性、持仓行情覆盖、价格观察和历史覆盖，并把恢复动作链接到对应来源而非首页。

### 设置与安全

此页承载 Passkey、TOTP、备份恢复、本机数据与低频偏好。它不存放显示币种、临时金额隐藏或日常刷新。

桌面使用固定侧边栏，390px 使用等价底部导航；每个一级目的地都有可访问名称、当前页状态、键盘路径和可靠返回路径。

## 数据健康与刷新体验

- 来源同步失败必须保留最后成功的总额和持仓，显式显示最后成功时间、过期状态、失败原因及重试入口；一次来源失败不阻塞其他来源。
- 来源总额、持仓明细覆盖、估值完整性、价格观察和同步健康独立表达。仅汇总产品或持仓行情不可用不会错误制造“总额异常”。
- 全局刷新仅服务总览；单来源手动刷新仅在对应来源详情。界面展示进行中、成功、失败和下一步，不用重复噪声通知遮挡阅读。
- 未估值资产不按零计入数值总额；过期资产继续计入最后成功金额但降低可信度。没有可折算金额时显示“无法折算”，不显示零。

## 安全、隐私与只读边界

- 保留服务端所有者授权、Passkey/TOTP、会话锁定、Keychain/SecretStore、断开与永久删除语义。
- 未认证 HTML、序列化状态、API、演示入口和网络响应不得包含真实或虚构资产总额、持仓、来源身份、历史曲线、收益、账本或可推断它们的形状。演示数据不再作为锁定页可进入的产品表面。
- 锁定页只保留所有者预置或登录、主题与非敏感本机时间。支持的资产来源品牌、资产汇总流程图、资产卡片构图及任何“进入演示”查询参数都不是锁定面内容。
- 不新增下单、交易、划转、提现、签名、钱包连接、私钥、助记词、多用户、公开分享、完整收支、税务或交易级成本法。

## 设计与交互原则

- 复用 `src/ui/vibe/`、既有运行时 Token 和锁定的 Vibe/Nothing 视觉合同；不引入第二套后台主题，不复制上游仓库。
- 金融数值优先于装饰：金额、币种、数据状态、可信度和下一步操作必须可扫读；红色仅表示风险或错误，不能用作普通图表装饰或激活态。
- 桌面、中屏、390px 手机、浅色与深色均需真实浏览器可用。控件保持可见焦点、键盘操作、最少 40px 命中面积，减少动态效果时不丢失状态信息。

## 验收与非目标

- 单元与集成覆盖账本、时间/汇率、完整性、缺失观测、资金补录、收益计算、来源总额优先与同步失败。
- 真实浏览器覆盖锁定页、总览、资产与持仓、收益分析、资金记录、来源、数据健康、设置与安全的桌面与 390px 核心流程；测试替身不能替代真实来源或硬件 Passkey 验收。
- 真实来源、真实凭证和实际账户一律不在本重构中主动使用；需要时必须由所有者明确授权。
- 指数同资金流比较需要数据提供方、许可与总回报口径的独立决策。本期只能显示“未配置/数据不足”，不抓取临时网页数据伪造基准。
