# 09 — 恢复隔离演示模式

**What to build:** 在锁定页恢复可访问的演示模式，用固定虚构数据展示工作台能力，同时与真实所有者数据、凭证、会话和本机持久化完全隔离。

**Blocked by:** 无。

**Status:** resolved

- [x] 锁定页和已认证总览提供清晰的“进入演示模式”入口；`/?mode=demo` 可在未认证状态下进入演示总览，并提供明确的退出入口。
- [x] 演示页保留 `DEMO DATA / NO PERSISTENCE` 标示，并使用当前 `DailyOverviewWorkspace` 的总览信息架构；全部来源、账户、金额和趋势均是固定视觉夹具，不从真实账户、来源服务或同步状态派生。
- [x] 演示模式仅使用进程内固定夹具：不初始化所有者服务、不读取或复用真实会话、不请求资产/来源/账本 API，不访问 SecretStore、Keychain 或 SQLite，也不读取或写入演示币种、趋势、分布维度或主题偏好。
- [x] 可能触碰真实服务或真实工作台的刷新与来源详情均不可用；演示内的显示、布局和主题操作仅在当前页面内存中生效。
- [x] 退出演示后返回首页：未认证时回到锁定页，已认证时回到真实总览；登录、退出、会话锁定、超时和受保护深链不共享任何演示或真实业务数据。
- [x] 自动化覆盖未认证直达、入口跳转、网络请求隔离、浏览器偏好隔离和退出流程；浏览器验收覆盖桌面与 390px 的可访问性、首屏与无横向溢出。

## 与 R07 的关系

R07 在 2026-08-09 基于当时的锁定面隐私合同移除了 `/?mode=demo` 和所有演示入口，该完成记录保持不变。本 Ticket 是后续产品需求变更：恢复演示能力，但以更严格的运行时隔离和不可持久化边界替代旧实现。

## 非目标

- 不接入真实账户、真实凭证、硬件 Passkey 或外部来源。
- 不增加交易、下单、划转、提现、签名、钱包连接、私钥、助记词或公开分享能力。
- 不借演示模式绕过所有者认证以访问任何真实工作台数据。

## 决策（2026-08-20）

- 所有者明确演示必须迁移到当前系统，而非复用已淘汰的资产卡片盘。演示使用 `DailyOverviewWorkspace`，保留固定示例来源与页头 `DEMO DATA / NO PERSISTENCE` 明示。
- 后续实现优先保证运行时隔离，而不是把演示页改造成第二套视觉语言：真实服务、请求、凭证、会话、SQLite 与浏览器偏好均不进入演示路径。

## 答案

- `src/app/page.tsx` 在调用 `getServices()` 前处理 `?mode=demo`，以固定 `createDemoDashboardData()` 驱动当前 `DailyOverviewWorkspace`；该路径不触达真实资产、凭证或会话服务。锁定页和已认证页均可进入，退出返回首页。
- 演示总览保留当前系统的计价、总资产、可信度、今日变化、趋势和来源摘要；刷新控件禁用且不会发请求，所有通往真实资产、来源或收益页面的链接替换为静态说明。
- 根层主题引导和工作台显示偏好均在演示查询参数下跳过 `localStorage` / `sessionStorage`；演示内容另以 `persist={false}` 的显示偏好 Provider 隔离，主题与计价等只在当前页面内存中生效。
- 自动化证据：`pnpm typecheck`、独立构建后的 `e2e/demo-mode.spec.ts` 与 `e2e/asset-only-dashboard.spec.ts` 共 4/4 通过；覆盖现代总览、无旧卡片盘、无资产 API 请求、浏览器偏好零访问和退出流程。
- 浏览器证据：桌面与 390px 访问 `/?mode=demo` 均渲染当前总览，演示标示可见、无横向溢出、无相关控制台错误；未使用真实账户、凭证或硬件 Passkey。
