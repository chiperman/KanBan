## Problem Statement

备份状态与载荷没有包含手工资产记录及正式日结。恢复会删除正式日结和来源，来源删除又级联删除手工资产记录；随后只回填备份已有的数据域，使恢复成功但历史事实丢失。

**审查证据：** 临时 SQLite 的公开导出—预演—恢复复现：来源/手工记录/日结数量从 1/2/1，经预演保持不变，恢复后变为 1/0/0。

**位置（模块/函数）：** BusinessDataState / BusinessDataBackupPayload、exportBackup、restore；生产数据库 replaceState 及手工记录外键。

## Solution

避免恢复操作造成不可重建的历史业务数据丢失。

**修改风险：** 中：涉及格式升级、恢复顺序与旧备份兼容。

## User Stories

1. 作为所有者，我希望保证手工资产记录与正式日结完整恢复，以便避免恢复操作造成不可重建的历史业务数据丢失。
2. 作为维护者，我希望用既有业务入口验证本 Ticket，以便修复不改变已接受的领域语义。
3. 作为所有者，我希望验收区分合成样例、自动化回归与真实环境结果，以便准确判断剩余风险。

## Implementation Decisions

- 升级版本化业务备份，完整纳入手工资产记录、正式日结及其来源/持仓证据，保留原始金额、币种、历史汇率、市场交易日和采集时间。
- 恢复前校验版本、校验和、唯一性、上海日期与引用关系；在同一事务中按依赖顺序替换，失败回滚。
- 继续支持既有版本 1—4 的读取。旧备份缺少数据域时预演必须明确列出缺失及目标库受影响范围；目标存在相关记录时默认阻止静默覆盖，只能在所有者明确确认丢弃后继续。不得从现值生成旧事实或混保目标库不相关记录。
- 保持凭证排除与本地文件 0600；自动来源恢复为无凭证的断开来源。手工资产记录保留可维护性和删除最新记录后回退语义。

## Testing Decisions

优先扩展现有无凭证备份恢复浏览器/HTTP 流程，并通过真实临时 SQLite 验证整套 roundtrip 和事务失败。禁止接触所有者业务库。

测试边界为建议方案，已向所有者征询，本规格发布时未收到确认；实施前以其反馈更新。测试只验证对外结果，避免对搬迁后的内部函数或特定 SQL 文本做镜像断言。

**验收标准：**

- [ ] 包含所有业务数据域的导出—恢复，除明确的自动来源断开/凭证排除转换外，历史事实逐项等价。
- [ ] 正式日结的父记录、来源和持仓证据均恢复；不使用后续行情或当前汇率重算。
- [ ] 手工来源同日唯一、编辑和删除可用；删除最新记录后当前总额回退到上一条。
- [ ] 预演不改库，并显示所有数据域及被替换范围；旧版缺失数据明确警示并按既定确认策略处理。
- [ ] 损坏载荷、非法引用、重复标识、非法日期均在覆盖前拒绝；恢复中途失败回滚，重复恢复不重复创建事实。
- [ ] 备份无任何平台/所有者认证秘密或秘密引用，权限仍为 0600；恢复不触发自动同步。

## Out of Scope

不备份凭证、不引入云同步、不恢复旧卡片编辑界面、不改变历史金融口径。
