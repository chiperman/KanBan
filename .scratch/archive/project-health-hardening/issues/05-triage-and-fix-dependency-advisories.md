## Problem Statement

审查时生产依赖审计报告 2 个 critical、5 个 high、2 个 moderate。命中公告不等于当前 macOS 部署具备全部攻击条件，需要同时确认运行平台、输入可控性与图像端点暴露。

**审查证据：** 2026-09-10 审查锁定 Next 16.2.11、PostCSS 8.4.31、Sharp 0.34.5、nanoid 3.3.16。记录的公告包括 GHSA-p293-qw3h-jr36、GHSA-2xp9-vwfh-vxw4、GHSA-rgj7-g3m4-5g8c；启动本 Ticket 时重新核对官方公告与锁文件。

**位置（模块/函数）：** 生产依赖声明与锁文件解析结果；框架图像优化入口及部署平台配置需只读核对。

## Solution

消除已知依赖风险，同时避免无依据的大范围升级。

**修改风险：** 中：框架及传递依赖升级可能影响构建和路由。

## User Stories

1. 作为所有者，我希望核对依赖漏洞暴露面并定向升级，以便消除已知依赖风险，同时避免无依据的大范围升级。
2. 作为维护者，我希望用既有业务入口验证本 Ticket，以便修复不改变已接受的领域语义。
3. 作为所有者，我希望验收区分合成样例、自动化回归与真实环境结果，以便准确判断剩余风险。

## Implementation Decisions

- 建立公告—安装版本—实际入口—影响条件—处置的清单，优先修复确认可达的严重与高危入口。Windows 专属或特定 Linux 条件不能直接套用于 macOS。
- 选取经当前公告核对的最小兼容修复版本；先通过上游依赖解决传递依赖，确需 override 时说明兼容性和撤销条件。
- 审查时记录的 Next 16.3.3、Sharp 0.35.4 等修复版本仅作线索，不能替代实施时核验；同时核对 PostCSS 与 nanoid 公告。

## Testing Decisions

复用既有安装、构建和浏览器/HTTP smoke；漏洞证据来自官方公告与依赖图。按实际变更面补路由/图片输入验收，不攻击运行中的个人实例。

测试边界为建议方案，已向所有者征询，本规格发布时未收到确认；实施前以其反馈更新。测试只验证对外结果，避免对搬迁后的内部函数或特定 SQL 文本做镜像断言。

**验收标准：**

- [ ] 审计中每条严重/高危公告都有已修复或基于证据的不适用说明；不能用总数下降代替逐条闭环。
- [ ] 确认实际图像优化入口、非可信图片来源与部署平台；缺少证据时保持待验证标记。
- [ ] 包清单与锁文件一致，冻结锁文件安装、类型检查、既有单元测试及必要认证/资产业务 smoke 通过。
- [ ] 记录变更前后依赖差异和剩余公告；构建在隔离环境执行，避免覆盖正在运行的共享构建产物。

## Out of Scope
