# 02 — 统一资产刷新 Coordinator

**What to build:** 建立唯一的资产刷新协调模块与服务端批次入口，统一处理每小时自动全量刷新、手动意图、目标合并、并发隔离、超时和多标签防重复。

**Blocked by:** 01 — 刷新状态与组合历史基础

**Status:** resolved

**Reference:** [资产刷新机制重设计](../spec.md)

## 范围

- 新增统一 `AssetRefreshCoordinator`，接收 `manual-global`、`manual-source`、`page-entry`、`foreground` 与 `interval` 意图。
- 自动刷新只使用一个统一一小时周期和一份单次定时计划，不按来源分别到期，不自动执行 prices-only。
- 自动批次必须同时满足页面可见、浏览器窗口有焦点、统一周期已到期；失焦期间不刷新，恢复后只重新判断一次。
- 手动全量始终可以申请执行并重置统一周期；手动单来源不受周期限制，也不改变统一周期。
- 客户端只减少无效请求；服务端原子判断周期、预占全量批次并阻止多页面、多标签重复读取。
- 同一批次来源并行读取，每个来源独立 60 秒超时；不同批次串行，同一来源不能并发读取。
- 合并重复意图和排队目标：在途全量可被复用，未开始的单来源队列可由后续全量意图吸收。
- 单来源 A 已开始后收到全量意图时，先完成 A，再执行包含 A 在内的完整全量批次，确保组合历史来自同一批次。
- 批次开始后不因页面隐藏、失焦、锁定、退出或进入演示模式而取消；客户端只与其脱离。
- 在途期间来源断开、删除、更换凭证或重新连接时，保存前重新核对来源生命周期和内部连接版本，安全丢弃失效结果。
- `superseded` 结果不计入成功或失败，不改写来源同步状态，也不显示错误。
- 最后一个可刷新自动来源消失后停止计划并按方案清除周期元数据；重新连接第一个来源时从新的连接成功时间建立周期。
- 浏览器关闭期间不运行 cron 或后台 worker。

## 验收标准

- [x] 自动全量仅在可见、有焦点且周期到期时开始；页面隐藏或失焦不请求，恢复后不补刷多个错过周期。
- [x] 下一次自动到期时间按实际批次开始时间加一小时计算，不按结束时间计算。
- [x] 自动批次成功、部分失败、全部失败或超时后都不快速重试，继续等待下一统一周期。
- [x] 手动全量可绕过周期但不能绕过在途批次保护；手动单来源不读写统一周期。
- [x] 页面进入、前台恢复与定时到期重叠时，只执行一份全量批次。
- [x] 多标签同时申请全量刷新时，来源 Adapter 只被调用一轮。
- [x] 同批来源并行且各自独立 60 秒超时；多个慢来源不会造成超时串行累加。
- [x] 一个来源失败或超时不阻止其他成功来源提交，且批次结果正确区分全部成功、部分失败与全部失败。
- [x] 全量、单来源和排队意图遵守方案中的复用、吸收与串行顺序，同一来源不会并发读取。
- [x] 每个实际服务端批次结束只发出一次数据重读信号；合并意图不会重复写组合历史。
- [x] 已开始批次不因页面状态或所有者会话变化被强制中断；未开始意图会在锁定、退出或演示模式时清除。
- [x] 断开来源的在途结果被丢弃但旧快照保留；删除来源的结果不能复活任何数据。
- [x] 连接版本变化后的旧结果以 `superseded` 结束，不能覆盖新连接快照、污染失败统计或写组合历史。
- [x] 在途来源集合变化不追加自动批次、不重置周期；下一周期使用最新来源集合。
- [x] 无可刷新来源时不创建定时器或请求；最后一个来源消失后按合同清理周期，重新连接第一个来源时重建周期。
- [x] 服务端异常中断后不自动重试；遗留进行中标记不形成永久锁，后续到期或手动全量仍可执行。
- [x] 使用假时钟与可控 Adapter 覆盖到期判断、意图合并、60 秒超时、多标签竞争、异常中断和来源生命周期变化。
- [x] 相关 Node 测试、协调器测试、服务端批次测试、`pnpm typecheck` 与 `git diff --check` 通过。

## 非目标

- 不在总览、资产、收益或来源详情页面挂载刷新入口。
- 不实现按钮样式、状态文案、辅助技术反馈或命令菜单接线。
- 不删除旧 `AssetRefreshControls`、自定义事件、OwnerDashboard 或其他 UI 代码。
- 不增加实时模式、30 秒行情轮询、后台 cron 或通知。

## 答案

已完成统一刷新协调器与服务端批次入口：

- 新增纯客户端 `AssetRefreshCoordinator` 与计划函数，统一处理五类意图、单次一小时定时器、可见/焦点资格、请求复用及 `clear()` 后与在途请求脱离。
- `SourceIsolatedAssetSynchronization` 以持久化状态原子预占全量批次，合并/串行排队目标，同批来源并行读取并施加独立超时；实际全量批次报告返回其真实开始时间。手动全量只绕过周期，不绕过未失效的进行中批次；单来源不改周期或组合历史。
- 补齐 SQLite 周期预占、最后一个可刷新来源消失后的周期清理及首个重新连接来源的重建；在途来源生命周期或凭证版本变化安全结束为 `superseded`。
- 未接页面、按钮、命令菜单或删除旧刷新组件，留给 Ticket 03。

## 评论

2026-08-26 审查阻断修正：

- API 现在拒绝无统一 `intent` 的 `sourceIds`、`sourceIds` 与旧 `sourceId`/显式 `scope` 混用，以及未包含 `manual-source` 意图目标的合并数组；非法请求不会触发统一或 legacy 同步入口，合法的 A + `[A, B]` 合并目标仍可执行。
- `not-due` / `in-progress` 跳过报告携带服务端当前全量 `attemptedAt`；新标签 Coordinator 会吸收锚点、静默回到 idle，并按锚点继续安排下一次检查。`no-sources` 仍允许无锚点。
- 新增两个独立 `SqliteDashboardDatabase` / `DatabaseAssetFullRefreshState` 实例竞争同一数据库文件的真实回归，结果仅一个 `claimed`、另一个 `in-progress`，双方读取到一致的 `attemptedAt` / `inProgressAt`。
- TDD 红灯证据：API 回归最初收到 200 而非期望的 400；skipped 合同测试最初 19 项中 6 项失败；SQLite 竞争用例最初因测试 action 尚未实现而失败。完成最小实现后，上述聚焦回归及完整命令均通过。
- 遗留问题：无。Ticket 03 的页面 UI、命令菜单与旧刷新组件清理均未接入。

2026-08-26 请求异常周期修正：

- 自动或手动全量底层请求直接 reject 时，以本次客户端尝试的开始时间建立保守周期，保持错误状态与错误消息，同时在一小时后继续统一尝试。
- 手动单来源请求 reject 不改写全量周期；服务端正常报告中的 `attemptedAt` 仍优先于客户端回退锚点。
