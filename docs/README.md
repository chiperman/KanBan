# 文档入口与维护规则

本文区分现行规则、未完成事项和历史证据。开始任务时先读所属现行文档，再沿源码入口核对实现；历史资料用于理解背景，不能直接作为当前需求或实施授权。

## 现行文档

| 入口 | 职责 |
| --- | --- |
| [CONTEXT](../CONTEXT.md) / [ADR](adr/) | 领域词汇、财务口径、业务约束与决策；ADR 按状态和替代关系阅读 |
| [当前能力与源码导航](current-baseline.md) | 当前页面职责、实现入口和验证边界；不汇总历次测试通过数量 |
| [DESIGN](../DESIGN.md) / [设计系统](design-system/README.md) | 视觉契约、组件规则和验收要求 |
| [工具链](operations/toolchain.md) | 安装、构建与开发环境约束 |
| [服务生命周期](operations/service-composition.md) | 服务装配、长桥读取链路与持久化生命周期 |
| [认证传输](operations/auth-transport.md) | 认证请求的传输约束 |
| [Agent 规则](../AGENTS.md) / [领域文档约定](agents/domain.md) | Agent 阅读顺序与文档维护要求 |

每项规则在所属文档维护一份，其他入口通过链接引用。业务合同或运行行为改变时，同次更新所属现行文档；保留合同的内部重构无需为改文档而改文档。页面职责或源码入口改变时更新 `current-baseline.md`。

现行文档与实现冲突时，先核实用户当前要求、已接受的决策、实际运行路径及相关测试，明确差异后再处理；不能仅凭旧规格恢复退役功能，也不能仅凭代码已存在就认定业务规则正确。

## 开发与待办

- 不强制 spec、本地 Ticket、任务地图、状态标签或固定文档模板；复杂问题先在会话中讨论范围、取舍和验收，临时计划放已忽略的 `tmp/<topic>/`。
- [未完成事项](backlog.md) 只保留跨会话需要跟进的问题与未完成验收。执行前核对源码；已实现的事项只补必要验收，完成后从清单移除。历史报告中的建议不自动变成开发任务。
- 生效规则更新所属现行文档。提交获授权后，用提交正文记录变更原因、行为变化、实际验证和未验证范围；无需为每次修改另写交付报告。

待办、会话计划和历史状态不构成执行、提交或部署授权。
