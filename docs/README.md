## 维护方式

- 每项规则在所属文档维护一份，其他入口通过链接引用。行为或合同改变时同步更新；保留合同的内部重构无需额外写文档。
- 文档与实现冲突时，结合当前要求、有效决策和实际运行路径明确差异，不能仅凭历史记录或现有代码判定业务规则。
- 小改不另写规格、计划或交付报告。临时调查放已忽略的 `tmp/<topic>/`，截图与日志放 `output/<topic>/`。
- 验证结果写在交付回复或获授权的提交正文中，说明实际范围；旧测试结果与历史授权不自动沿用。

## 目录与命名

| 位置 | 保存内容与命名 |
| --- | --- |
| `docs/` 根层 | 文档索引、`current-baseline.md`、唯一待办 `backlog.md` 与第三方声明 |
| `docs/adr/` | 需要长期保留取舍的领域决策；沿用稳定的 `0001-<topic>.md` 编号，替代关系在原文说明，索引链接原文 |
| `docs/design-system/` | 基础、组件与页面规范；实际 Token 和配方维护在运行时源码 |
| `docs/operations/` | 工具链、来源接入、服务生命周期与认证传输 |

普通主题文件使用小写英文和短横线，ADR 保持既有编号。移动、合并或删除文件时，同步入口、文内链接及脚本引用。项目源码与本机文件的职责见 [根 README](../README.md#目录职责)。
