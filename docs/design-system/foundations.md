# 基础规范：视觉、字体与点阵

本文维护视觉基础与允许的适配。运行时值以 [design-tokens.css](../../src/app/design-tokens.css) 为实现入口，采用范围与验证方式见 [设计契约](../../DESIGN.md)。表中值用于解释当前刻度，不在页面另写一套常量。

---

## 1. 色彩

灰阶承担层级，一屏灰色不超过 4 种。正文使用柔白／柔黑，标题和主数字可使用 `--display`。明暗与跟随系统的主题选择沿用运行时能力，不把工作台写死为暗色。

### 1.1 画布与表面

| Token | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--bg` | `#000000` | `#f2f2f2` | 页面画布（OLED 黑 / 暖灰纸） |
| `--surface` | `#0c0c0c` | `#ffffff` | 菜单、弹层、对话框底色 |
| `--raised` | `#171717` | `#ededed` | 次级抬升、悬停行、缩略图与键帽填充 |
| `--overlay` | `rgba(0,0,0,.88)` | `rgba(242,242,242,.9)` | 模态遮罩 |
| `--glass` | `rgba(16,16,16,.9)` | `rgba(255,255,255,.96)` | 玻璃卡填充，必须与 `backdrop-filter` 成对使用 |
| `--glass-brd` | `rgba(255,255,255,.09)` | `rgba(0,0,0,.08)` | 玻璃卡可选的内侧 1px 细线 |

### 1.2 文本层级

| Token | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--display` | `#ffffff` | `#000000` | 标题、主数字、反转填充 |
| `--primary` | `#ededed` | `#1c1c1c` | 正文与默认图标色 |
| `--secondary` | `#8c8c8c` | `#585a5a` | 标签、次级说明 |
| `--muted` | `#5a5a5a` | `#9a9a9a` | 最弱文字、占位符、刻度 |

### 1.3 线条

| Token | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--line` | `#262626` | `#e2e2e2` | 列表、表格、分区之间的分隔细线 |
| `--line-2` | `#3a3a3a` | `#cfcfcf` | 控件轮廓、可见边框、分段条空槽 |

结构分隔细线为 1px，不靠加粗表达强调；焦点轮廓按组件规范处理。状态标记遵守 [项目适配](../../DESIGN.md#项目适配)。

### 1.4 信号

| Token | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--accent` | `#d71921` | `#d71921` | 信号红**填充**：需要决策、越限、录制/实时点、通知角标 |
| `--accent-text` | `#ff4438` | `#c2141c` | 强调色作为**前景**（文字/边框/图标），暗色提亮、亮色压深以保对比 |
| `--accent-ink` | `#ffffff` | `#ffffff` | 红底之上的文字色 |
| `--restricted-dot` | `rgba(255,255,255,.12)` | `rgba(0,0,0,.14)` | 受限内容的点阵纹理，**不承载金额语义** |
| `--dotbg` | `rgba(255,255,255,.48)` | `rgba(0,0,0,.42)` | 上游遗留 token，当前点场不使用 |

**强调色规则（不可协商）**

1. 强调色只用于真实信号：需要决策的计数、`NEEDS INPUT`、越限数值、实时点、通知角标、语义告警，以及强调色色板本身。
2. 典型一屏 **0–2 个红色元素**。判断标准很直接：如果去掉这个红色之后界面没有任何信息损失，那它就是装饰，不该存在。
3. **填充与前景是两枚 token**。红底白字用 `--accent` + `--accent-ink`；红字/红边/红图标用 `--accent-text`。不得把填充红直接当文字色使用。
4. 常规按钮、标签页、链接、滑块、悬停态、选中芯片和开关 ON 不用强调色。危险操作的前景色与下拉选中小色块沿用 [组件规范](components.md) 中的限定，不扩展成红色操作填充。

### 1.5 数据状态

| Token | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--success` | `#5bc96b` | `#247e37` | 正常、已连接、已启用、已成功完成 |
| `--warning` | `#f2c94c` | `#9c6b00` | 待确认、待更新、需要注意 |
| `--error` | `#ff5247` | `#d23b30` | 明确失败或不可用；与强调色同属一个红色家族 |

状态色用于相关数值、状态圆点或小色块，以及必要的状态文字与图标；普通标签与表头保持中性，不整行染色。内联通知的局部底色按组件配方处理。状态必须同时有明确文字，具体映射见 [状态映射](components.md#状态映射)，涨跌呈现见 [页面模式](patterns.md#金融信息与隐私)。Token 的主题变体不能替代实际对比度检查。

### 1.6 图表分类色

收益率市场对比是**分类数据**，不是涨跌状态。标普 500 使用 `--benchmark-spx`，纳斯达克 100 使用 `--benchmark-ndx`；两者在暗色和亮色主题分别提供高对比值。颜色必须与图例、曲线、tooltip 和指数选择控件中的色标保持一致，不表示上涨、下跌、风险或推荐。我的收益率与标普 500 使用连续实线并以白色／蓝色区分，纳斯达克 100 使用黄色点线；线型与颜色同时保留，避免只依赖单一视觉通道。

### 1.7 兼容别名

`--black` `--dark-grey` `--grey` `--light-grey` `--white` 是上游早期命名的中性色别名，仅供历史样式引用。新代码改用上表的分层 Token。

## 2. 字体排版

五种角色，各有其职。层级由字号跳变与角色区分承担，**不靠字重与颜色堆叠**。

| 角色 | Token | 家族 | 用途 |
|---|---|---|---|
| 点阵显示 | `--f-display` | Doto | 字标、主数字、独字数字与其百分号、时钟、模块编号 |
| 界面/正文 | `--f-ui` | Geist | 正文、说明文字 |
| 等宽/数据 | `--f-mono` | Geist Mono | 大写标签、数据、代码、表格单元格、时间戳 |
| 标题 | `--f-head` | Geist（600） | 卡片标题、对话框标题、分区标题 |
| 编辑体强调 | `--f-editorial` | Newsreader Italic | 仅页面级的一句品牌文案或引语 |

### 2.1 强制规则

- **Doto 字重上限 500**，且必须保留 `font-variation-settings: "ROND" 100`。加粗会让相邻圆点粘连、曲线顶端出现尖角（数字 `0` 会长出尖顶）。
- **编辑体斜体的边界是页面级 vs 组件级**：它只允许出现在页面级文案（一句 hero、一句引言，一屏至多一句），**绝不出现在任何可复用组件内部**——按钮、输入框、卡片、表格、导航、弹窗、标签、列表、看板磁贴一律无衬线。
- 技术标签用 `--f-mono` + 西文全大写 + 字距 `.08–.14em`；中文不强行大写或过度拉开字距。
- 金融数值使用 `font-variant-numeric: tabular-nums` 保证跨行对齐。
- 中文正文由 `--f-ui` 自动回退到 `PingFang SC` → `Noto Sans SC` → 系统无衬线，这是本产品的适配层规则，不改变上游视觉契约。

### 2.2 排版级差

字号分**两族**，不要互相替代。给正文用展示档会让字号突然跳档，给大数字用正文档会让它淹没在页面里。

**文字族**（排句子与标签，步长密集）

| Token | 值 | 真实用途 |
|---|---|---|
| `--vibe-type-heading` | 24px | 卡片标题、分区标题 |
| `--vibe-type-subheading` | 18px | 小节标题、对话框标题、来源标题 |
| `--vibe-type-title` | 20px | 小标题与仪表数字共用的一档：身份名、锁定时钟、验证码格、趋势区间数字 |
| `--vibe-type-body` | 16px | 输入控件、说明正文 |
| `--vibe-type-body-sm` | 14px | 次级正文 |
| `--vibe-type-body-xs` | 13px | **产品的正文基准**——`body` 元素本身用的就是这一档；对话框正文、下拉触发器、日历格、次级按钮文字、空态提示同属这一层 |
| `--vibe-type-caption` | 12px | 注释、时间戳、次级说明 |
| `--vibe-type-label` | 11px | 等宽大写标签、表格表头、单位 |
| `--vibe-type-micro` | 10px | 最小一档的等宽大写微标签：字段标签、眉标、快捷键提示 |

**展示族**（排"一屏一个的大数字"）

| Token | 值 | 真实用途 |
|---|---|---|
| `--vibe-type-display-xl` | 72px | 总览资产总额 |
| `--vibe-type-display-lg` | 48px | 总览金额、登录门标题 |
| `--vibe-type-display-md` | 36px | 当日变动金额、手机登录页标题 |
| `--vibe-type-display-sm` | 26px | 趋势卡里的昨日／区间数字 |

字号采用本表的项目刻度，不混用上游展示站的完整序列；13px 正文与 10/11px 标签是有效角色，不要求字号为 4px 倍数。新增档位必须有真实用途，并在 Token 中定义。

已有例外：`.locked-flow-screen text`（9px）与 `.locked-flow-dashboard-label`（8px）位于 [登录页](../../src/ui/owner-login.tsx) 的 SVG 内，使用随 `viewBox` 缩放的图纸单位，不适用界面字号刻度；不要据此放宽普通文字。

## 3. 间距

间距以 4px 为基准，使用下表 Token；2px 是已采用的微调档位，不单独发展一套刻度。

| Token | 值 | 关系语义 |
|---|---|---|
| `--vibe-space-0` | 2px | 图标、文字等紧邻元素的微调 |
| `--vibe-space-1` | 4px | 触碰级（图标与文字之间） |
| `--vibe-space-2` | 8px | 同组内 |
| `--vibe-space-3` | 12px | 同组内上限 |
| `--vibe-space-4` | 16px | 组件内边距 |
| `--vibe-space-5` | 20px | 面板内边距 |
| `--vibe-space-6` | 24px | 模块内边距 |
| `--vibe-space-8` | 32px | 新分组 |
| `--vibe-space-10` | 40px | 新分组 |
| `--vibe-space-12` | 48px | 新语境 |
| `--vibe-space-16` | 64px | 新语境 |
| `--vibe-space-24` | 96px | 页面级留白 |

**当你伸手去拿一根分隔线时，通常真正需要的是更多留白。**

## 4. 圆角

| Token | 值 | 适用 |
|---|---|---|
| `--r-sm` | 6px | 控件、按钮、输入框、状态标签 |
| `--r-md` | 8px | 卡片、对话框、面板 |
| `--r-pill` | 999px | 芯片、开关轨道、头像 |

**卡片圆角不得超过 8px，也不得使用大胶囊。** 圆角不是表达层级的工具——层级由细线与留白建立。

## 5. 层次

不使用投影表达深度，层次由 z-index、细线、留白与材质表达。存量 `box-shadow` 中的焦点或几何绘制需先分类，不能因名字包含 shadow 就删掉可访问性线索；待处理范围统一见 [backlog](../backlog.md#存量样式与守门基线收敛)。

| 层 | z-index | 用于 |
|---|---|---|
| base | 10 | 常规内容 |
| overlay | 30 | 下拉菜单、下拉选项面板 |
| modal | 40 | 对话框 |
| header | 50 | 吸顶页头 |
| floating | 80–120 | 提示浮层及浮动变体 |

例外说明：玻璃卡的 `backdrop-filter: blur()` 是**材质**，不是阴影。它表达"这是一层玻璃"，而不是"这层浮在上面"。

## 6. 动效

| 场景 | 值 | 说明 |
|---|---|---|
| 微交互 | `200ms` · `ease-in-out` | 控件、边框、透明度 |
| 主题切换 | `350ms` · `ease-in-out` | 仅颜色与背景 |
| 悬停 | `opacity .8`（按钮）；卡片可不动，采用位移时不超过 `-2px` | 不增加装饰色或阴影，选择项底色按组件配方处理 |
| 按下 | `opacity .6` | 机械、干脆 |
| 禁用 | `opacity .3` | 特殊进行态可局部放宽（如刷新中为 `.68`） |

常规过渡用 `--ease`（`ease-in-out`），时长用 `--vibe-duration-fast` / `--vibe-duration-theme`。没有弹簧、回弹、缩放弹出或视差；动效优先使用透明度，位移克制。

数据类动效（如计数滚动）统一为 1200ms 三次缓动，滚动进入视口后才启动，并遵守减弱动效偏好。

`prefers-reduced-motion: reduce` 下移除非必要运动或让其立即完成，计数直接落位，装饰旋转停止，状态文字始终保留。现有全局规则也覆盖遗留层元素，不能仅凭某份 CSS 没有单独媒体查询就断言未覆盖。减弱动效中的既有 `!important` 优先级覆盖属于允许手段。

## 7. 控件尺寸

| Token | 值 | 说明 |
|---|---|---|
| `--vibe-control-height-compact` | 40px | 紧凑控件（菜单触发器、菜单项） |
| `--vibe-control-height` | 44px | 标准按钮、下拉；字段输入的实际配方为至少 48px |
| `--vibe-control-padding-inline` | `var(--vibe-space-4)` = 16px | 水平内边距 |

紧凑交互目标至少 40px，标准与移动端交互目标至少 44px；可见轮廓更小时通过外扩命中区满足要求。静态标签不按交互控件计算。键盘与焦点要求见 [组件规范](components.md#通用交互与无障碍)。

## 8. 点阵语言

独立数字、百分比、时钟、日历日期和页码使用 Doto；数字与 `%` 保持同一字体单元，`USD` / `GB` 等字母单位使用小号等宽字体。数据表与极小的行内计数可以用等宽字体，金融数值不能为点阵效果牺牲可读性。

- [VibeDotIcon](../../src/ui/vibe/vibe-dot-icon.tsx) 使用 9×9 网格，每个亮点必须是完整圆点。尺寸由 `--vibe-dot-icon-size` 驱动，间距等比缩放，不用 `mask` / `clip-path` 裁切图标点阵。
- [VibeIcon](../../src/ui/vibe/vibe-icon.tsx) 承担按钮、输入和导航的功能性小图标：1.5px 单色线形 SVG、22px 视口、圆端圆角、`currentColor`，不填充、不多色。
- 25×25 设备字形与专用点阵标点按真实场景再引入，采用时核对固定上游规则；不因上游存在就提前补齐。
- 装饰性点阵不编码金额、来源身份或授权状态。独立的 SVG 亮度遮罩（如 `.locked-flow-route-reveal` 的白色 stroke）不是主题前景色，不能改成会随明暗反转的 `--display`。

## 9. 背景点场

层级为 **Background → Dots → Card**：点在卡片下方，只在模块缝隙与边缘可见，不覆盖卡片内容。

当前配方在 [vibe-components.css](../../src/app/vibe-components.css) 的 `body::before`：固定全屏点层、`z-index: -1`、`pointer-events: none`，以半透明白点和 `mix-blend-mode: difference` 获得局部反色，不为两套主题各维护一种点色。

| 项目 | 约束 |
| --- | --- |
| 点形 | `radial-gradient` 的实心半径约 1.3px，透明过渡到约 1.7px |
| 间距 | `120px 120px`，保持稀疏，不与正文竞争 |
| 附着 | 页面点场使用 `background-attachment: fixed`，各模块延续同一视口网格 |
| 独立背景区 | 确有自己的不透明背景时，以 `position: relative`、`isolation: isolate` 建立独立点层；不默认给每张卡片加点 |

点场中的白色 `rgba()` 是混合配方的必要输入，属于明确例外。禁止装饰性渐变；背景点场可保留。

## 10. 对比度

正文文字至少 4.5:1；大字（至少 24px，或至少 18.66px 的粗体）至少 3:1；需要辨识的控件边界、焦点和图形至少 3:1。`--muted` 不承担操作所必需的信息，状态不靠颜色单独传达。明暗主题均需核对实际前景与底色的组合。
