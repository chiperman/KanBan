# 06 · 治理

规范的寿命取决于更新它的成本。这套规范把更新成本压到一条命令——因为样式指南是生成物，不是手写文档。

---

## 1. 权威顺序

1. **`DESIGN.md`** — 采用契约与上游固定版本。冲突时以它为准。
2. **本目录（`docs/design-system/`）** — 规范展开与治理记录。
3. **`styleguide.html` / `tokens.json`** — 渲染证据与机器可读导出。

如果发现本目录与 `DESIGN.md` 冲突，**先修本目录**，并在 `07-deviation-register.md` 记录一次。

---

## 2. 变更流程

### 2.1 新增或修改界面

1. 读本目录与 `DESIGN.md`，再读固定 commit 的上游 [`SPEC.md`](https://github.com/wangbh030722/vibe-nothing-ui-design/blob/46661e55ae04537215a229be49f2ac1bd37a4255/SPEC.md)、`index.html`、`DESIGN.md`。
2. 需要新组件时，**先组合，再新增**：按 token + 细线 + 黑白反转 + 等宽大写标签 + 玻璃的规则组合，并对齐最近的既有模块的视觉密度。
3. **不引入任何第二套 CSS 框架、reset 或字体。**
4. 复用 `src/ui/vibe/` 的 React 组件；不要在页面里重复配方。
5. 改动 token 或组件配方后，重新生成样式指南并跑一次验收：`pnpm design:styleguide && pnpm design:styleguide:verify`。
6. 交付前跑 `pnpm test`（已含 `design:lint`），并跑一遍第 5 节的检查清单。
7. 在 `docs/design-system/` 更新受影响的文档段落。

### 2.2 更新上游引用版本

**这是一个显式的设计任务**，不能顺带做：

1. 在 GitHub 上比较当前与拟采用的上游 commit；
2. 逐项审阅规范、可视样例、token、组件配方与许可证的差异；
3. 更新 `DESIGN.md` 与本仓库 `AGENTS.md` 中的固定链接；
4. 有意识地适配本地 React 模块与运行时样式；
5. 跑聚焦的浏览器验收与完整相关回归；
6. 在提交信息中记录旧、新两个引用 commit。

**上游 `main` 分支的任何变化都不自动生效。** 专有字体（NDot、NType、Lettera 等）不得从非官方镜像获取、提交或再分发。

---

## 3. 分层职责边界

| 层 | 文件 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| 上游契约层 | `src/app/design-tokens.css` | 定义 token、字体加载 | 承载业务选择器 |
| 组件配方层 | `src/app/vibe-components.css` | 组合 token 成可复用配方 | 引入新语义、写业务选择器 |
| 产品适配层 | `src/app/product-layout.css` | 布局、密度、业务表达 | 新造视觉语言、覆盖 token 值 |
| 遗留层 | `src/app/globals.css` | 逐步迁出 | **新增任何样式** |

`src/app/globals.css` 建立于设计系统之前，保留了硬编码色值、字体栈与圆角，并含有已确认的死代码。参见 [`07-deviation-register.md`](07-deviation-register.md)。**新代码一律不写入该文件。**

## 4. 组件缺口

上游契约中存在、本产品尚未组件化的能力。**补做时必须沿用上游语义，不得另起命名。**

| 缺口 | 上游契约 | 现状 |
|---|---|---|
| 开关 Switch | 药丸轨道 + 圆旋钮；ON = `--display` 轨道 + `--bg` 旋钮，**不用红** | 无组件，仅有 `.vibe-choice` 复选 |
| 滑块 Slider | 细轨道 + 圆旋钮，填充与旋钮用 `--display` | 无对应场景，未实现 |
| 仪表 Gauge | 细环 + 刻度环 + 居中 Doto 数字，`%` 紧随数字不换行 | 用分段条替代 |
| 标签页 Tabs / 分页 Pager | `.tabs` 2px `--display` 下划线；`.pager` 用 Doto 页码 | 用分段条 + 图标按钮替代 |
| 线性进度 Progress | `.lp`：`--display` 填充 | 用分段条替代 |
| 横幅 Banner | 默认反转填充；`.sig` 红底白字**仅限需要决策的消息** | 用 `.vibe-notice` 内联承载 |
| 空态 Empty state | 虚线边框 + 9×9 点阵字形 + 标题 + 一个主按钮，不用插画 | 配方未组件化；现网实现为细线变体 |
| 点阵标点 | `.colon` / `.pdot` / `.ellip`，直径由 `--pxd` 控制 | 无点阵排字场景，未实现 |
| 25×25 字形矩阵 | 25×25 圆形遮罩网格、几何函数生成 | 无设备级点阵场景，未实现 |
| 统一状态机 | `idle` / `running` / `needs-input` / `done` / `error` | 已通过状态标签的 6 个色调近似表达，但未固化为组件层契约 |

## 5. 交付前检查清单

### 视觉契约

- [ ] 输出中零裸值：没有硬编码颜色、px 圆角、字体名；全部来自 token
- [ ] 一屏红色元素 ≤2 个，且都是真实信号
- [ ] 所有激活态都是**黑白反转**，不是上色（按钮主态、选中芯片、今日日期、当前步骤、开关 ON）
- [ ] 零 `box-shadow`、零渐变（点场与点阵纹理除外）
- [ ] 卡片无边框、圆角 ≤8px、悬停仅 `translateY(-2px)` 或不动，绝无阴影

### 字体

- [ ] 功能性 UI 全部无衬线；Newsreader 斜体**只出现在页面级文案**，绝不在组件内部
- [ ] 独立数字与其百分号用 Doto；标题与正文用 Geist；标签与数据用 Geist Mono
- [ ] Doto 字重 ≤500，`ROND=100` 生效（点分离、`0` 无尖顶）

### 点阵与点场

- [ ] 点阵图标是完整圆点（grid 单元格，无 `mask` / `clip-path`）
- [ ] 点场：`difference` 混合、`z-index: -1`、约 1.3px / 约 120px、`fixed` 附着
- [ ] 独立背景区域自带点层，区域内的点同样局部反色
- [ ] 点不出现在卡片表面或前景内容上

### 状态与真值

- [ ] 状态先由形状与标签表达，颜色只作第二层
- [ ] 缺失估值显示为「未估值」，**未折算为零**，并使总额标明汇总不完整
- [ ] 「持仓行情未接入」未降低总额估值完整性
- [ ] 金额保留完整精度、等宽对齐、显式币种
- [ ] 未回显任何凭证原文、密钥或助记词

### 主题与响应式

- [ ] 暗色与亮色都验证过
- [ ] 产品工作台保持暗色
- [ ] 390×844 下 `document.scrollWidth === 390`
- [ ] 新增样式只使用 0 / 640 / 1024 / 1200 四档断点

### 无障碍

- [ ] 正文对比度 ≥4.5:1，大字 ≥3:1
- [ ] 全部功能可键盘完成，焦点可见，对话框焦点循环
- [ ] 交互命中区 ≥40px
- [ ] 减弱动效下过渡消失但**状态文字保留**
- [ ] 文本放大 200% 不破版

### 工程

- [ ] `pnpm typecheck` 通过
- [ ] 相关浏览器验收通过
- [ ] 浏览器控制台无应用错误
- [ ] 改动 token / 配方后已运行 `pnpm design:styleguide`
- [ ] `pnpm design:styleguide:verify` 通过（样式指南本身的渲染验收）
- [ ] `pnpm test` 通过（`typecheck` → `design:lint` → `test:unit` → `test:smoke`）

## 6. 何时必须重新生成样式指南

| 触发 | 原因 |
|---|---|
| 修改 `src/app/design-tokens.css` | token 值、明暗两套值、字体加载都会变 |
| 修改 `src/app/vibe-components.css` | 组件配方与样张渲染结果会变 |
| 修改 `src/ui/vibe/vibe-icon.tsx` 或 `vibe-dot-icon.tsx` | 图标集与字形比特会变 |
| 更新上游引用版本 | 契约引用与固定 commit 会变 |

生成器在源文件结构发生破坏性变化时会**直接抛错**（例如线形图标数少于 8、字形不是 9×9），而不是产出一个静默错误的页面。看到报错时修生成器，不要绕过它。

**不要手工编辑 `styleguide.html`。** 它会在下一次生成时被完全覆盖。

## 7. 守门脚本：让偏差不再扩大

规范文档能说明规则，但拦不住新代码继续引入裸值。第 5 节检查清单里**可以机械判定**的那几条已经固化成脚本：

```bash
pnpm design:lint            # 校验，出现基线外新增即失败
pnpm design:lint -- --update  # 存量减少后重建基线
```

脚本是 `scripts/lint-design-tokens.mjs`，基线是 `scripts/design-system/token-lint-baseline.json`。10 条规则、当前 68 处存量豁免，明细见 [`README.md`](README.md) §4.2 与 [`07-deviation-register.md`](07-deviation-register.md) §0。

三条使用纪律：

1. **看到 `design:lint` 失败，先改代码，不要先改基线。** 基线是"历史欠账账本"，不是"允许清单"。真要放宽，必须先在 `07-deviation-register.md` 登记，说明为什么这次例外成立。
2. **修掉存量后立即重建基线**，否则账本数字虚高，下一次真正的违规会被淹没在噪声里。`--verbose` 会列出所有"可收紧"的条目。
3. **不要改脚本的刻度来源。** 字号级差是从 `design-tokens.css` 现读的——要让一个新字号合法，正确做法是新增一档 `--vibe-type-*` token 并同步本目录文档，而不是往脚本里加白名单。

**按设计豁免只写进规则，不写进基线。** SVG 用户坐标系里的字号（`SVG_TEXT_SELECTORS`）不是欠账，基线只该记录待偿还的存量。这条界限要守住，否则基线会变成"什么都允许"的清单。

**`undefined-design-token` 是回报最高的一条规则。** 它跨文件比对 `var(--x)` 的引用与定义，第一次运行就抓出 11 处静默失效的声明（D-21）——不报错、不留痕，靠读代码几乎不可能发现。改动 token 命名后务必跑一次。

**`page-button-override` 阻止按钮语言再次分裂。** 它禁止页面级 CSS 覆盖 `.vibe-button` / `VibeButton` / `VibeLink` 的视觉属性，只保留布局属性；认证页与首次供给页按 D-22 范围豁免。新增 React 页面按钮时先选 `VibeButton` / `VibeLink` 的封闭属性，不要另写按钮类名。

> 本脚本已接入 `pnpm test`，作为 `test:design` 步骤在类型检查之后运行。

## 8. 处理已登记偏差的原则

1. **只登记，不伺机修改。** 产品代码的变更需要独立任务与独立验收。
2. 修一项偏差时，同步更新 [`07-deviation-register.md`](07-deviation-register.md) 的状态列，并在提交信息中引用其编号。
3. 死代码优先清理（风险最低）；其次是新增代码的规范约束（防止继续扩大）；最后才是有视觉影响的整改。
4. **不要在整改中顺带改视觉**。一次提交只做一件事，否则无法判定回归来源。
