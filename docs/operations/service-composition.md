# 生产服务生命周期

- `composition.ts` 的进程级槽保存服务。重复请求及兼容模块重载复用同一对象；独立 CLI 进程拥有自己的服务。
- `production.ts` 只组装端口；`persistence/` 持有数据库、迁移和适配器，`credentials/` 保存秘密与所有者认证，`source-connections.ts` 协调授权与业务状态。旧公开导出继续兼容。
- SQLite 实例独占其连接，启动依次设置 PRAGMA、Schema 迁移、完整性校验和权限收紧。旧 JSON 不在运行时导入；需要迁移时单独执行 `pnpm migrate:json-to-sqlite`，迁移入口会校验目标库为空并保留源文件备份。Schema 模块借用该连接和事务，不自行连接。初始化失败关闭连接；正常连接与服务同寿命，由进程退出回收。
- 秘密恢复在读取来源引用后执行；ReadySecretStore 和来源连接等待同一恢复 Promise，失败向调用者传播。
- 长桥生产数据读取统一使用已登录的 CLI/serve：资产与报价刷新、授权后账户预览、指数、持仓 K 线、近五日走势和正式日结行情均不回退到 Keychain SDK。Keychain 仍负责现有 OAuth 授权与本地来源身份绑定；账户读取会前后核对 CLI 身份，失败保留上次资产快照。
- 修改服务端口、缓存格式或底层存储实现后应重新启动应用。兼容热更新用于已有服务的复用，不保证替换进程中已存在的类实例。
- 离线生命周期测试使用临时目录，覆盖新进程、模块重新求值、重复获取和重启数据保留；CLI 测试单独验证命令入口。历史验证只对应其提交与运行范围，不能代替当前真实服务器验收。

## 后台自动采集

- [后台服务](../../src/server/background-collection.ts) 独立于浏览器会话。Mac 用户登录后，网页生产服务常驻，采集任务每分钟检查一次；到期后执行每小时全量读取，失败来源在该轮开始后第 5、15 分钟补试。时间按轮次开始计算，不固定在整点；补试与手动单来源刷新不重置小时周期。网页自动刷新复用同一持久化周期。
- 每次检查也按十五分钟间隔调用正式日结执行器，仍遵守独立收盘窗口。使用综合后台时，不要同时保留旧的独立日结任务。睡眠、关机期间不运行；恢复后处理到期任务，不补造遗漏日的数据。
- SQLite 按来源保存带 token 与过期时间的租约，覆盖网页、后台、手动和正式日结读取；租约比单来源超时预算多五秒，进程退出后可过期接管。原子提交核对来源身份、凭证、生命周期和时间顺序，同一事务写入最新快照与当日累计观测；旧 token 不能提交或释放新租约。
- 设置中的状态查询只读，不触发采集。心跳表示近期检查过，批次结果表示读取情况，今日覆盖表示当日有效观测，两者不能互相替代；首次完整时间来自当日基准。来源授权过期仍需重新授权，网页登录过期或关闭网页不停止后台。
- 后台心跳、补试计划和租约属于运行状态，不进入业务备份；历史观测、基准和正式日结仍按已有业务备份合同保存。

### 永久运行副本

后台不能长期指向会被移除的开发 worktree。先准备独立源码、依赖与生产构建，再安装登录任务：

```sh
pnpm runtime:prepare "$HOME/Library/Application Support/KanBan/runtime-v1" \
  --data-dir "$HOME/Library/Application Support/KanBan/data" \
  --env-file /绝对路径/.env.local --port 3001
cd "$HOME/Library/Application Support/KanBan/runtime-v1"
pnpm background:launchd print
pnpm background:launchd install
pnpm background:launchd status
```

[准备脚本](../../scripts/prepare-runtime.mjs) 不覆盖已有目录，不复制业务数据，也不安装任务；它复制当前源码（包括未提交且未忽略的修改）与经校验的原生产物，独立安装依赖和构建，保存 `.kanban-runtime.json`。构建使用一次性空数据目录，不接触正式库。运行副本禁止 `pnpm dev`。

日常开发完成后，在开发仓库根目录执行：

```sh
pnpm runtime:update
```

[更新命令](../../scripts/update-runtime.mjs) 自动读取已安装的网页与采集任务，要求两者属于同一个 3001 正式副本，沿用其数据目录、`.env.local` 和登录入口；不会复制开发数据或替换来源凭证。`pnpm runtime:update --check` 只检查配置、显示更新目标，不构建或切换。

新版在独立目录安装依赖并构建，期间旧版继续提供网页和采集。构建失败保留旧版；构建通过后暂停新后台批次并等待当前批次退出，再短暂重启网页、切换任务。更新通过进程锁互斥；切换前使用 SQLite 在线接口保存数据库和原任务至新版 `.runtime-rollback/`，不直接复制可能遗漏 WAL 的主文件。启动后校验新构建的静态资源、首页及后台实际检查心跳；失败自动恢复原任务，保留正式数据库。旧副本保留用于回退，不自动清理。

采集的小时锚点、补试计划和历史记录仍来自同一个正式数据库，不因更新重置；切换期间到期的任务在恢复后处理。更新进程存活时后台跳过新批次，进程异常退出后暂停标记不阻塞采集。若进程被强制杀死而遗留更新锁，应先核对锁目录 `owner.json` 中的进程与任务实际状态，再移除锁重试。自动回退恢复代码与任务，不自动覆盖已写入的业务数据；不兼容的数据结构变更仍需独立迁移方案。网页服务重启后可能需要重新登录，Passkey、备用登录及来源授权继续沿用。

首次沿用现有数据时，先停止旧服务，完整备份并复制原数据目录，包括 SQLite、凭证、所有者认证与外部服务配置；保留原 `PAD_SECRET_ENCRYPTION_KEY`。不要让旧版开发进程与新版后台并行写正式库。开发默认端口 3000，正式副本默认 3001，使用不同数据目录与构建目录；复制的数据从分离后各自独立。

[launchd 管理脚本](../../scripts/background-launchd.mjs) 创建当前用户的 `com.xiaox.kanban.web`（持续运行）和 `com.xiaox.kanban.background-collection`（每分钟检查），固定 Node、PATH、数据目录与登录入口，日志保存在正式数据目录。默认入口为 `http://localhost:3001`；需要远程入口时用 `--origin` 指定现有 HTTPS 入口，并同步其转发端口。所有者登录保护保持生效；本机采集不需要网页 Cookie。

`pnpm background:run` 是一次真实后台检查，必须显式提供绝对路径 `KANBAN_DATA_DIR`，拒绝 `APP_ENV=test`；排查时不能将它当演示命令运行。安装、移除任务与真实数据迁移分别按本次操作授权执行。

## 正式日结

- [日结执行器](../../src/server/formal-daily-settlement.ts) 使用独立只读采集与持久化，不调用实时刷新的记录写入路径，不改写实时资产快照、当日基准或每日趋势观测。
- 持有证券时按相关市场交易日历及已确认的常规盘日 K 收盘确定锚点；无证券时使用上海自然日加密资产截点。休市、半日市与夏令时不能由固定钟点代替。
- 每个锚点只保存一批记录；[SQLite 写入](../../src/server/persistence/sqlite-formal-settlements.ts) 通过唯一键忽略重复插入，重复运行或进程重启不能覆盖既有金额。窗口外记录漏采，不用后续持仓、价格或汇率补造历史总额；证据不足明确降级。
- [CLI](../../scripts/run-formal-daily-settlement.ts) 与页面使用同一服务装配和 `KANBAN_DATA_DIR`。本机 [launchd 管理脚本](../../scripts/formal-daily-settlement-launchd.mjs) 的安装、启停不是构建或启动页面的副作用，需明确操作授权。
- 设置页的 [调度状态读取](../../src/server/formal-settlement-scheduler.ts) 只查询本实例配置与加载证据，不安装任务、不采集资产，也不把“已加载”解释为采集健康或真实验收通过。未完成事项见 [待办](../backlog.md)。
