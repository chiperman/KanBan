# 个人资产看板全站 UI/UX 与可访问性审查

审查日期：2026-07-28
审查范围：当前工作区、本地受控会话、暗色主题、桌面 Chrome、移动端 CSS 断点
审查方式：实际页面观察、DOM 语义检查、只读样式测量与相关代码核对

## 1. 结论

产品的安全边界与核心数据结构已经清楚：锁定状态不展示资产、首次预置强调唯一所有者、来源接入先验证再保存、永久删除具备两次确认。这些基础应该保留。

当前最影响完成度的并不是功能缺失，而是登录后看板出现了四类不一致：

1. **敏感恢复材料暴露过早**：打开备用登录配置就立即生成并明文展示 TOTP 密钥，弹窗也缺少可访问名称。
2. **产品状态表达不一致**：锁定页使用上海时间，登录后页头改为 UTC；“汇总完整”与“今日资产变动·数据不完整”同时出现，却没有解释两者检查的对象不同。
3. **视觉权重失控**：所有来源卡片重复使用 3px 高对比度顶边，Doto 大数字、白色分段条和危险操作同时争夺注意力。
4. **边界页面与移动流程未收口**：预置完成后 `/setup` 落入框架默认英文亮色 404；移动端来源弹窗占满整个视口，选择来源与填写表单混在同一长页面。

建议先做 6 个 P1 修复，再处理宽屏与移动端结构。无需整体重做，也不建议顺手更换字体、颜色或卡片体系。

## 2. 审查目标

主要用户目标：所有者能够快速、可信地查看当前资产，理解数据是否完整，并安全管理只读资产来源。

可访问性目标：

- 重要状态不只依赖颜色；
- 正文与元数据在暗色背景上可读；
- 弹窗具有明确名称、合理焦点顺序和可见的退出路径；
- 常用触控目标至少 44×44px；
- 页面在移动断点下不发生横向溢出；
- 不把静态检查误报为完整 WCAG 验收。

## 4. 已确认的优点

### 4.1 锁定页没有泄露资产信息

锁定状态只有身份验证入口，不显示资产卡片、来源身份或金额。主标题、操作按钮和安全属性的顺序清楚，符合单所有者终端的安全边界。

### 4.2 首次预置把不可逆性说清楚了

预置页明确说明“仅可完成一次”“注册入口永久关闭”，按钮名称也直接指向 Passkey。页面没有加入无关营销内容。

### 4.3 总资产概览的主要层级成立

总资产数字仍是页面第一视觉焦点，计价货币、分布维度、今日变动、资产分布和趋势都能被读屏结构识别。总资产卡没有再套一层厚重容器。

### 4.4 来源接入在保存前有验证与确认边界

选择来源后才出现相应字段，按钮在必填信息不足时保持禁用。代码中 API Secret / Passphrase 使用密码输入，观察钱包明确只查询公开地址。

### 4.5 永久删除具备双确认

第一阶段说明会删除来源、持仓、同步记录和快照；代码中第二阶段才提供最终删除按钮。审查只打开第一阶段并取消，没有执行删除。

## 5. 优先级问题与改进建议

### P1-01：备用登录在打开弹窗时立即暴露 TOTP 密钥

证据：打开“配置备用登录”后，接口立即生成配置选项，原始密钥作为只读文本框直接出现。弹窗根节点只有 `role="dialog"` 和 `aria-modal="true"`，没有 `aria-label` 或 `aria-labelledby`。相关代码见 `src/ui/recovery-setup.tsx:22`、`:71`、`:87`。

影响：

- 肩窥、录屏、截图或浏览器扩展可能读取恢复密钥；
- 仅仅打开配置入口就创建了敏感材料，用户尚未明确进入生成步骤；
- 读屏用户只会听到“对话框”，无法立即知道用途。

建议：

1. 第一步只说明用途、风险和所需材料，用户点击“开始配置”后再生成密钥；
2. 默认遮蔽原始密钥，提供“显示一次”和“复制”操作；
3. 优先提供标准二维码，同时保留手动密钥作为备用；
4. 关闭或取消时立即清除前端状态，并让未保存密钥在服务端失效；
5. 给弹窗增加 `aria-labelledby`，标题使用真实 `<h2>`；
6. 若产品安全模型允许，生成或更新恢复材料前要求一次 Passkey 再验证。

验收标准：打开入口时不出现密钥；只有明确继续后才生成；取消后旧密钥不能继续保存；读屏能读出“配置备用登录”。

### P1-02：预置关闭后显示框架默认 404

证据：受控会话中，已预置状态访问 `/setup` 显示框架默认 404；`src/app/setup/page.tsx:11` 直接调用 `notFound()`，仓库没有产品化的 `not-found.tsx`。

影响：亮色背景、英文文案和默认排版造成强烈跳变；所有者无法判断是入口已关闭、服务故障还是地址错误。

建议：为应用增加产品化 404，并在 `/setup` 已关闭时显示专用状态：

- 标题：“所有者已完成预置”；
- 说明：“预置入口已永久关闭，请返回所有者登录页”；
- 操作：“返回登录”；
- 不暴露凭证详情，不提供再次注册入口；
- 同时覆盖暗色与亮色主题。

验收标准：已预置状态访问 `/setup` 时不出现英文或默认框架页面，键盘可直接返回登录页。

### P1-03：锁定页与已登录页使用两套时间语义

证据：锁定页显示 `SHANGHAI / 21:xx`，已登录页头显示 `2026-07-28 13:xx UTC`。`src/app/page.tsx:13` 和 `:75` 明确格式化为 UTC。

影响：同一产品切换身份状态后时间倒退 8 小时；来源更新时间与页面时钟的理解成本增加。

建议：

- 页头统一使用上海本地时间；
- 数据观测时间采用“07-28 21:37 上海”或“刚刚 / 6 分钟前”，详情中再保留标准时区；
- 所有日期组件共享同一格式化函数，不在页面组件中单独拼 UTC 字符串。

验收标准：锁定与解锁状态在同一时刻显示同一小时；所有绝对时间明确标出“上海”或偏移量。

### P1-04：来源卡片的 3px 高对比度顶边不符合当前设计规则

证据：桌面与移动受控会话均观察到该顶边；`src/app/nothing-system.css:2064` 为每张普通卡片设置 `border-top: 3px solid var(--ink-display)`。

影响：每张卡片都获得接近主数字的视觉权重；白线、分段条、Doto 金额和红色危险按钮同时竞争，破坏“三层层级”。

建议：删除这条特殊顶边，保留完整的 `1px solid var(--line-strong)` 或只使用表面色差。不要用另一条装饰线替代。

验收标准：来源卡片四边权重一致；总资产数字仍是眯眼测试下唯一的第一视觉焦点。

### P1-05：完整性状态的对象不清楚

证据：同一屏同时显示“汇总完整”“今日资产变动・数据不完整”和趋势行“不完整”。当前代码分别检查当前估值、今日基准和历史快照，但 UI 没有说明差异，见 `src/ui/total-asset-overview.tsx:102`、`:169`、`:203`。

影响：用户会自然理解为系统自相矛盾，不知道当前总额是否可信。

建议：把状态名称改为对象明确的三类：

- `当前估值：完整`；
- `今日变动：基准不完整`；
- `历史快照：不完整`。

今日变动旁提供一句可展开说明，例如“今日基准缺少一个来源，金额仅供参考”。

验收标准：任何“完整/不完整”前都有明确对象；当前总额可靠但今日变动不完整时，用户无需猜测原因。

### P1-06：11px 灰色元数据存在暗色对比度风险

实测可见的页头时间、来源状态、分段条说明和来源控制状态大量使用 11px；其中部分颜色为 `rgb(102, 102, 102)`。在黑色或 `#111` 背景上，这类小字低于普通文本常用的 4.5:1 目标。

建议：

- 11px 只用于非必要装饰编号；
- 时间、状态和操作说明至少 12px；
- 必要元数据使用 `--ink-secondary`，不要使用 `--ink-muted`；
- 保留低对比度只用于纯装饰点阵和无语义编号。

验收标准：所有必要文本达到 4.5:1；200% 缩放下不截断；状态说明不依赖颜色。

### P2-01：超宽桌面没有有效利用横向空间

证据：桌面受控会话中，当前 `.page` 使用 `width: min(100%, 1280px)`，在超宽显示器上形成大面积左右空白，而来源卡片仍挤在 2+1 的窄列中。

建议：

- 保留总资产内容的可读行宽，但让来源网格在宽屏扩展至 1440–1600px；
- 总览可继续两列，来源区域单独使用更宽的 12 列网格；
- 不要简单放大字体填满空间。

验收标准：在 1920px 和 2560px 宽度下，来源卡片得到实际增益；总览文字行宽仍可读。

### P2-02：来源接入弹窗把“选择”和“填写”混成一个长步骤

证据：来源选择、API 表单、观察钱包表单和移动端来源弹窗的受控会话均显示该问题；移动实测弹窗约为 `500×1125px`，高度与视口几乎完全相同。

建议改为两个机械、短促的步骤：

1. 选择来源；
2. 显示所选来源的权限说明与字段。

移动端使用全屏 sheet，标题和返回按钮固定在顶部，主要操作固定在底部，中间内容独立滚动。API 来源在字段前展示“只读权限检查清单”，观察钱包则说明地址公开性与支持网络。

验收标准：移动端打开弹窗时标题、退出操作和主按钮始终可见；用户可以返回来源选择而不丢失已输入字段。

### P2-03：危险操作长期占据每张来源卡片

证据：桌面和移动卡片底部同时显示“隐藏、断开、永久删除”。虽然删除有两次确认，但红色永久删除按钮在日常浏览时持续出现。

建议：卡片正文只保留日常操作；“断开”和“永久删除”移入“来源管理”面板或更多菜单。移动端将来源控制做成独立行，而不是扩展卡片正文长度。

验收标准：日常看板不直接展示永久删除按钮；仍可在两步以内进入来源管理；双确认保留。

### P2-04：`LOCAL / READ ONLY` 容易被误解

页面同时声明 `LOCAL / READ ONLY`，又提供断开和永久删除本地数据。技术上“只读”指外部账户权限，但界面没有说清楚对象。

建议改为 `EXTERNAL ACCESS / READ ONLY`，中文辅助说明为“资产来源权限：只读”。本地数据管理另用“本机数据”语义。

验收标准：用户能区分“不能交易/转账”和“可以管理本地记录”。

### P3-01：头部次要操作挤占移动端首屏

移动端在品牌和时间后立即展示“配置备用登录、快捷命令、立即锁定”三个同权按钮。它们都不是查看资产的首要动作。

建议：保留“立即锁定”为直接操作，其余收进快捷命令或一个“本机设置”入口。不要使用新的图标体系，仅减少常驻按钮。

## 6. 推荐实施顺序

### 第一批：安全与产品真相

1. 延迟并遮蔽 TOTP 密钥，补弹窗名称；
2. 产品化 `/setup` 关闭状态与 404；
3. 统一上海时间；
4. 重写完整性状态文案。

这批不改变卡片布局，风险最低，能先修复信任问题。

### 第二批：视觉层级与可读性

1. 删除普通卡片 3px 顶边；
2. 提升必要元数据的字号与对比度；
3. 只让总资产保留最强 Doto hero 权重；
4. 将来源管理危险操作移出卡片正文。

### 第三批：响应式与来源工作流

1. 来源接入拆成选择与填写两步；
2. 移动端采用固定标题/操作区的全屏 sheet；
3. 宽屏来源网格扩展到 1440–1600px；
4. 减少移动页头常驻操作。

## 8. 证据限制

- Chrome 的响应式视口覆盖实际落在约 500px，但已进入 `max-width: 639px` 的移动样式；本轮没有覆盖 390px。
- 未提交 API 凭证、未启动 OAuth、未保存备用登录、未断开或删除来源、未执行备份恢复、未退出登录。
- 备用登录弹窗包含真实 TOTP 密钥，因此相关截图已删除，文档只保留代码和可见行为结论。
- 本轮检查了 DOM 结构、可见焦点样式规则、目标尺寸和颜色风险，但没有使用真实屏幕阅读器完成整条操作流程，不能宣称 WCAG 全量通过。
- 页面在审查期间持续同步行情，观测金额与时间可能略有变化；这不影响布局与交互结论。
- 当前工作区包含用户已有的未提交修改；审查采证阶段没有修改产品代码，后续第一轮实施改动见下一节。
